## 3. 본부가 이미 확인한 것 (재조사 불필요)

spec (`_workspace/20260727_mktg2026_rerun/06_deck_spec.json` page_id p09):
- `layout: split`
- 블록 = eyebrow · headline · viz(donut) · body · metric × 2 · **note** · footnote · citation × 3

렌더 HTML 구조 (`deck.html`)는 정상 — `.split-body`(2열 grid) 다음에 `.split-note-row`가 **형제로** 온다. 절대 위치 아님.

CSS 실측 (`.claude/skills/deck-harness/scripts/render_deck.py` 안 스타일 문자열):
```
.body            { flex:1; min-height:0; overflow:hidden; display:flex; flex-direction:column; gap:24px; }
.split-outer     { display:flex; flex-direction:column; justify-content:center; gap:14px; }
.split-body      { flex:1 1 auto; min-height:0; display:grid; grid-template-columns:1fr 1fr; gap:48px; align-items:start; }
.split-note-row  { margin-top:18px; }
```

**본부 진단**: `.split-body`가 `flex:1 1 auto` + `min-height:0`이라 자기 콘텐츠보다 작게 압축된다. 압축된 높이를 좌우 칸 내용이 넘으면 grid 밖으로 흘러 note-row 자리에 겹쳐 그려진다. `.body`의 `overflow:hidden`은 슬라이드 경계 밖만 자를 뿐 형제 사이 겹침은 못 막는다.

**이 진단을 그대로 믿지 말고 먼저 재현으로 확인할 것.** 틀렸으면 틀렸다고 보고서에 쓰면 된다 — 그게 더 값지다.

### (2) CSS 수정 — 밴드 봉인

`.split-body`(와 같은 결함이 있으면 `.stack` 계열도)가 콘텐츠보다 작게 압축되지 못하게 한다. 방향 제안이지 명령은 아니다:
- `min-height:0` 제거 또는 `min-height:min-content`
- note-row 등 전폭 행에 `flex-shrink:0`을 줘서 전용 높이를 먼저 확보
- 어느 쪽이든 **좌우 칸 내용이 grid 영역 밖으로 나가지 않는 것**이 목표

수술적으로. 손댄 줄만. 전체 CSS 재작성 금지.
