## 0. 본부가 이미 실측한 것 (재조사 불필요)

전 실덱 45개·본문 페이지 555장(headline 있는 장만)에 두 후보를 적용해 봤다:

| 후보 | 걸리는 양 | 내역 |
|---|---|---|
| **B** 시각물 2종 이상 | **83장 / 15.0%** | metric+viz 80장 · metric+table 3장 |
| B 중 **note까지 있는 장** | **39장 / 7.0%** | ← p07·p09가 이 유형 |
| **C** 부제·단위 없는 viz | **171개 / 사실상 전부** | before_after 53·gap_map 36·big_number 19·dumbbell 18·mirror_bars 16 등 |

**이 숫자가 설계를 정한다:**

- B를 "시각물 2종 = 반려"로 바로 만들면 **본문의 15%가 걸린다.** 너무 세다. 반면 진짜 사고(겹침)를 낸 유형은 **note까지 얹힌 39장**이다. → **B는 2단계로 간다** (아래 §1)
- C는 걸리는 게 아니라 **spec 스키마에 필드 자체가 없다.** 즉 오검출 문제가 아니라 전량 신규 작업이고, 기존 덱은 소급 적용이 불가능하다(수치 출처를 다시 봐야 부제를 쓸 수 있다). → **C는 옵션 필드 + 경고로 시작한다** (아래 §2)

## 1. 후보 B — 한 장에 시각물 1종

**근거**: 티어A 4부가 전부 지킨다. 맥킨지는 32장에 도표 19개인데 도표 2개짜리 장이 한 장도 없고, 아래 절반이 비어도 두 번째 차트를 안 넣는다. KPMG는 "한 장에 시각물 유형 1종, 개수 2개까지". 한화증권은 병렬 증거를 동형 2-up으로만 둔다.

### B-1 (반려 게이트로 넣는다)

**`viz` + `metric`류 + `note`가 한 페이지에 같이 오면 반려.** 39장 대상.

이게 p07(92.1px)·p09(66px) 겹침을 낸 조합이다. 오늘 오전에 넣은 예산 가산이 이미 이 조합을 OVERFLOW로 잡지만(p09 561px vs cutoff 479), **예산은 높이가 아슬아슬하면 통과시킨다.** 문법으로 한 번 더 막는다.

- 반려 메시지에 **왜 걸렸는지와 어떻게 푸는지**를 같이 낸다: "차트와 숫자 카드를 나누거나, note를 다음 장으로 옮기세요"
- `LAYOUT_ALGORITHM.md` B.2(블록 동거 금지)에 규칙 번호를 이어서 추가하고, 근거로 이 실측(39장/555장)을 적는다

### B-2 (경고로만 둔다·반려 아님)

**`viz` + `metric`류가 같이 오면 경고** (note 없어도). 83장 대상.

15%를 한 번에 반려로 만들면 기존 덱이 무더기로 막힌다. 경고로 쌓아 두고, 다음에 실제 겹침·과밀이 얼마나 나오는지 보고 승격 여부를 후추님이 판단한다. **임의로 반려로 올리지 말 것.**

## 2. 후보 C — 차트 제목 3층 + 단위 1회 선언

**근거**: 맥킨지 전 차트 페이지가 이 형식이다 —

```
Exhibit 3                                       ← 눈썹 (도표 번호)
AI를 쓰는 조직은 늘었지만 수익까지 간 곳은 적다.    ← 결론 문장 (마침표로 끝남)
AI 도입 단계별 비율, % of respondents             ← 무엇을 쟀나 + 단위
```

개별 숫자에는 % 를 안 붙이고 부제에서 1회 선언한다. KPMG는 축 모서리에 (천 명)·(%)·(세), 한화증권은 캡션 우측에 "(단위: 억 원)" 1회. 3부가 같은 규격이다.

### 구현

1. **viz 블록에 선택 필드 3개 추가**: `exhibit`(눈썹·문자열) · `subtitle`(측정 대상 + 단위·문자열) · 기존 `title`은 결론 문장 자리로 그대로 쓴다
2. **렌더러**: 세 필드가 있으면 3층으로 그린다. 없으면 **지금과 똑같이 그린다** (기존 덱 출력 불변이 조건이다 — 회귀 확인 필수)
3. **게이트**: `subtitle`이 없으면 **경고 1줄**. 반려 아님. 171개가 전부 걸리므로 반려로 만들면 아무 덱도 못 나간다
4. `LAYOUT_ALGORITHM.md`에 절 하나 추가. "단위는 부제에서 1회 선언, 개별 수치에는 단위 기호를 안 붙인다"를 규칙으로 명시

**하지 말 것**: 기존 덱 45개의 spec을 고쳐서 부제를 채우려 들지 말 것. 부제는 그 수치가 무엇을 잰 것인지 원문을 봐야 쓸 수 있고, 그건 사람이 할 일이다.

## 3. 검증

- 두 후보 각각 **RED→GREEN 단위 검사**. 최소 형태로. 프레임워크·픽스처 늘리지 말 것
