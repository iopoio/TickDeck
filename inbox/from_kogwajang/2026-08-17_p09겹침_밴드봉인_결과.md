# p09 겹침 밴드 봉인 결과

## 1. 재현·원인

- 본부 진단은 맞았다. 현행 `.split-body`는 `flex: 1 1 auto`와 `min-height: 0` 때문에 내용보다 작게 축소될 수 있고, 칸 내용은 축소된 grid 경계를 넘어 형제 `.split-note-row` 범위에 그려질 수 있었다.
- 화면 바이너리는 실행하지 않았다. p09 spec·registry와 현행 CSS/조판 산식만으로 재현했다.
- 추가 원인: `layout_budget.evaluate_layout()`은 split의 실제 구조인 `lead + max(left, right) + note 전폭 행`을 모델링하지 않고 모든 블록을 직렬 합산했다. split 전용 note 행 가산 경로가 없었다.

## 2. 변경 파일

- `.claude/skills/deck-harness/scripts/render_deck.py`: split grid를 내용 높이로 봉인하고 note 행 축소를 금지했다. split/stack 직계 형제의 세로 범위가 겹치면 `TICKDECK_SIBLING_OVERLAP` 콘솔 경고를 내는 자동 검사를 추가했다. 실패 전환은 하지 않았다.
- `.claude/skills/deck-harness/scripts/layout_budget.py`: 렌더러와 같은 split 분배와 `lead + max(left, right) + note 전폭 행` 높이 계산을 추가했다. 형제 세로 범위 겹침 순수 검사 함수 `sibling_vertical_overlaps()`를 추가했다.
- `.claude/skills/deck-harness/scripts/test_layout_budget.py`: note 전폭 행 가산, 형제 겹침 검출, split 예산 판정 회귀 검사를 추가했다.
