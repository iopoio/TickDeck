## 2. 3/4 공통 — 수치 규격 (딜로이트는 통계 0개라 표본에서 제외)

- **단위는 1회만 선언**한다. 맥킨지 = 부제에서 "% of respondents" 1회 후 개별 숫자에 % 안 붙임 / 한화 = 캡션 우측 "(단위: 억 원)" 1회 + 표 전체 통일 / KPMG = 축 모서리 (천 명)·(%)·(세).
- **데이터 포인트 직접 라벨**. 축 눈금 읽기를 시키지 않는다 (맥킨지·KPMG 전 포인트, 한화는 주인공 선만 굵게).
- **출처는 해당 요소 직하단 1줄**. 맥킨지 = "출처명+표본+기간" / 한화 = "자료:"·"주:" 접두 / KPMG = "Source: ... 재구성"(가공 여부 명시).
- 소수 자리 고정: 맥킨지 정수 %, KPMG·한화 소수 1자리.

## 3. 우리 조판 v2와의 갭 — p09 표본이 정확히 '가' 위반

**표본** = `20260727_mktg2026_rerun` p09 (`p09_pptx_겹침표본.png`·`p09_html_동일결함.png`). "당장 할 일은" note 밴드가 16.1% 카드를 파고든다. PPTX와 HTML 양쪽에 있으니 export 탓이 아니라 조판 문제.

**실물 확인 (8/17 본부)**:

- spec = `layout: split`, 블록 = eyebrow · headline · viz(donut) · body · metric × 2 · note · footnote · citation ×3
- 렌더 HTML 구조는 정상 순서 — `.split-body`(2열 grid) 다음에 `.split-note-row`가 형제로 온다. 절대 위치 아님.
- CSS 실측:
  - `.body { flex:1; min-height:0; overflow:hidden; display:flex; flex-direction:column }`
  - `.split-body { flex:1 1 auto; min-height:0; display:grid; grid-template-columns:1fr 1fr }`
  - `.split-note-row { margin-top:18px }`
- **원인**: `.split-body`가 `flex:1 1 auto` + `min-height:0`이라 **자기 콘텐츠보다 작게 압축된다.** 좌우 칸 내용(donut + 본문 / 카드 2장)이 압축된 높이를 넘으면 grid 밖으로 흘러나오고, 그 자리에 note-row가 그려져 겹친다. `.body`의 `overflow:hidden`은 슬라이드 밖만 자를 뿐 형제 사이 겹침은 못 막는다.
- **게이트도 못 잡았다**: `LAYOUT_ALGORITHM.md` B.1이 이미 "**donut 페이지의 상한은 본문 1줄·note 없음**"이라고 적어 놨는데 p09는 donut + 본문 + metric 2 + note 조합으로 통과했다. 규칙이 문서에만 있고 예산 판정이 split을 좌우 병렬로 계산하면서 note 행을 별도 가산하지 않은 것으로 보인다 (재현 검사 필요).

즉 p09는 **'가'(자기 열·자기 밴드 밖으로 안 나감)와 '다'(한 장 시각물 1종) 두 개를 동시에 위반**한 페이지다. 티어A 4부는 이 조합 자체를 애초에 안 만든다.

## 4. 조판 v2 갱신 후보 3개 (우선순위 순)

### 후보 A — 밴드 봉인 (band containment) · p09 직결 · **오늘 실행 대상**

`.split-body`·`.stack` 계열이 콘텐츠보다 작게 압축되지 못하게 하고(`min-height:0` 제거 또는 `flex-shrink:0`), note·footnote 같은 전폭 행은 자기 전용 행 높이를 먼저 확보한 뒤 남은 공간을 본문 밴드에 준다. 더해서 **렌더 후 요소 겹침 자동 검사**를 붙인다 — 지금은 사람 눈으로만 발견된다(8/16 우연 발견).

- 근거 = 4/4 공통 '가'. 티어A는 전부 "요소는 자기 영역 밖으로 안 나간다"를 구조로 강제한다.
- 성격 = 버그 fix (규칙 신설 아님). 후추님 결재 없이 진행 가능.
- 검증 = p09 재렌더 육안 + 전 실덱 회귀.

### 후보 B — 한 장 시각물 1종 게이트

본문 페이지에 `viz`와 `metric`(카드)을 섞지 않는다. 섞을 경우 note 금지. 문서 B.1에 이미 있는 "donut 페이지 상한"을 게이트가 실제로 강제하게 한다.

- 근거 = 4/4 공통 '다'.
- 성격 = **규칙 신설 → 후추님 결재 필요.** 기존 덱 다수가 걸릴 수 있어 오검출 규모를 먼저 실측해야 한다 (Round 4에서 차트류 게이트 때 했던 것과 같은 방식 — 전 실덱 43개 적용).

### 후보 C — 차트 제목 3층 + 단위 1회 선언

`visual-title` 한 줄짜리를 3층으로: 눈썹(도표 번호) / 결론 문장 / 측정치+단위 부제. 개별 숫자에서 단위 기호를 빼고 부제에서 1회 선언. 출처는 해당 시각물 직하단.

- 근거 = 4/4 '나' + 3/4 수치 규격.
- 성격 = 규칙 신설 + 렌더러 확장 → 결재 필요. B보다 비용 큼(spec 스키마에 필드 추가).

## 5. 안 가져오는 것 (일부러 버림)

- 맥킨지 "3~4장마다 대형 인용 호흡 페이지" — 우리 덱은 16장 안팎이라 리듬 페이지를 넣으면 증거 페이지가 줄어든다. 30장+ 리포트의 문법.
- 딜로이트 "2장 짝 빌드(같은 도식 확대)" — 웨비나 티저용. 우리 산출물은 읽는 덱이라 같은 도식을 두 장 쓰는 비용이 크다.
- KPMG "좌측 인용 레일" — 세로형(540x780) 전용 문법. 우리는 가로 1280x720이라 28% 레일을 빼면 본문이 죽는다. 단 "한 장 한 메시지를 40자로 압축"이라는 정신은 headline이 이미 담당.
- 한화 "러닝헤더 전 페이지 반복" — 우리는 eyebrow chip + 페이지 번호로 이미 있음.
