# 리서치 → 리포트 → 덱 제작 워크플로우 가이드

앞서 진행한 "AI와 화이트칼라 업무" 프로젝트에서 실제로 사용한 프로세스를 단계별로 정리한 문서입니다.

---

## 전체 플로우 한눈에

```
① 요구 정의 → ② 리서치 → ③ 리포트 합성 → ④ 슬라이드 플랜 →
⑤ 코드로 덱 생성 → ⑥ 파일 검증 → ⑦ 시각 QA → ⑧ 납품
```

핵심 원칙: **각 단계의 산출물이 다음 단계의 입력이 된다.** 리서치 없이 리포트를 쓰지 않고, 리포트 없이 슬라이드를 만들지 않으며, 렌더링 확인 없이 납품하지 않는다.

---

## ① 요구 정의 — 조사 단위를 먼저 쪼갠다

- 질문을 그대로 검색하지 않고 **조사 단위(unit of analysis)를 먼저 정의**한다. 이번 건은 "직업"이 아니라 "태스크"가 단위였고, 그래서 모든 조사가 `역할 × 태스크 × (자동화/인간/신규)` 매트릭스로 수렴했다.
- 요구사항을 체크리스트로 변환한다: 필수 출처(BLS, WEF, 컨설팅사, 채용 데이터), 필수 섹션(방법론 충돌, 반대 신호, 시장 규모), 품질 기준(임원 브리핑급).
- 이 체크리스트가 마지막까지 "빠진 것 없나"를 검사하는 기준이 된다.

## ② 리서치 — 검색 전략과 증거 등급

### 검색 방법
- **쿼리는 짧게(1~6단어), 넓게 시작해서 좁혀간다.** "WEF Future of Jobs 2025 tasks" → 결과를 보고 "Stanford ADP entry-level" 식으로 구체화.
- 최신성이 중요한 주제는 연도를 쿼리에 포함한다.
- 검색 스니펫만 믿지 않고, 핵심 출처는 **원문 페이지를 직접 확인**한다(수치·날짜·표본 크기 검증).
- 비슷한 쿼리를 반복하지 않는다 — 새 정보가 안 나온다.

### 소스 우선순위
1. **1차 소스**: 정부 통계(BLS·OECD), 학술 논문(arXiv·NBER), 기업 공시·실적발표
2. **기관 리포트**: WEF, 컨설팅사(McKinsey·PwC 등), 플랫폼 데이터(LinkedIn·Indeed)
3. **언론 보도**: 1차 소스로 가는 경유지로만 사용
4. **애그리게이터/블로그**: 원출처 확인용 단서로만

### 증거 등급제 (이번 프로젝트의 실제 위계)
| 등급 | 유형 | 예시 |
|---|---|---|
| 1 | RCT·행정 마이크로데이터 | METR 무작위 실험, Stanford/ADP 급여 데이터 |
| 2 | 플랫폼 사용 데이터 | Anthropic Economic Index |
| 3 | 고용주 설문 | WEF, PwC |
| 4 | 이론적 노출 모델 | Goldman 300M, McKinsey 자동화 잠재력 |
| 5 | 벤더 자기보고 | Klarna "700명분", GitHub Copilot 55% |

**모든 수치에 등급을 태깅**하고, 낮은 등급은 반드시 "self-reported / 방향성 참고" 플래그를 단다.

### 반대 신호 의무 수집
- 주장을 뒷받침하는 자료만 모으면 확증편향에 빠진다. **"이 주장이 틀렸다는 증거"를 별도 쿼리로 반드시 검색**한다. (예: AI 생산성 → METR의 19% 느려짐, MIT의 95% 파일럿 실패)
- 같은 주제에서 숫자가 충돌하면 버리지 말고 **"무엇을 측정했기에 다른가"를 설명**한다. 이게 오히려 리포트의 신뢰도를 만든다.

## ③ 리포트 합성 — 피라미드 구조

- **결론 먼저**: TL;DR(3줄) → Key Findings(5개) → Details(역할별 상세) → Recommendations → Caveats. 임원은 위에서부터 읽다가 멈춘다.
- **주장–근거–출처 3종 세트**: 출처 없는 주장은 쓰지 않는다. 수치에는 항상 맥락(기준 시점, 비교 대상, 표본)을 붙인다.
- **반복 프레임워크**: 역할별 섹션을 전부 같은 3분할(AI 흡수 / 인간 잔존 / 신규 태스크)로 구성. 독자가 두 번째 섹션부터는 구조를 예측할 수 있게.
- **Caveats 섹션은 필수**: 지역 편향, 자기보고, 상관≠인과, 데이터 시점 한계를 명시. 한계를 스스로 밝히는 리포트가 더 신뢰받는다.

## ④ 슬라이드 플랜 — 코드를 짜기 전에 텍스트로 설계

덱을 바로 만들지 않고, 먼저 **슬라이드 플랜을 텍스트로 작성**한다:

```
S6 | 제목(주장문): "가장 명확한 실현 효과: AI 노출 직군의 신입 고용 감소"
   | 시각: 막대차트 (22–25세 −13% vs 35세+ +9%)
   | 사이드카드: 데이터 배경 4줄
   | 출처: Stanford/ADP (Brynjolfsson et al.)
```

### 슬라이드 설계 규칙
- **1 슬라이드 = 1 주장.** 제목은 명사구가 아니라 **완결된 문장**("개발자 현황" ✕ → "루틴 코딩은 자동화, 아키텍처는 인간 잔존" ○). 제목만 읽어도 스토리가 통하는지 확인한다.
- **스토리 아치**: 표지 → 요약 → 방법론 → 매크로 → 핵심 증거 → 역할별 상세 → 반대 신호(중간중간 배치) → 신흥 역할 → 시장 규모 → 증거 위계 → 권고 → 캐비앗 → 클로징.
- 반대 신호를 뒤에 몰지 않고 **관련 주장 바로 뒤에 배치**한다(개발자 태스크맵 다음에 METR 슬라이드).
- 데이터가 있으면 차트, 구조가 있으면 카드, 단일 수치면 대형 스탯 콜아웃 — **시각 형식을 플랜 단계에서 결정**한다.

## ⑤ 덱 생성 — 코드로 만든다

- 수작업 대신 **스크립트(pptxgenjs)로 생성**한다. 이유: 재현 가능, 일괄 수정 용이, 일관성 보장.
- **헬퍼 함수로 일관성을 강제**한다: `contentSlide()`(제목+킥커), `card()`(3열 카드), `statStrip()`(하단 인사이트 바), `sourceLine()`(출처 라인), `chartFrame()`(차트 공통 스타일). 슬라이드마다 개별 코딩하면 반드시 어긋난다.
- **차트는 네이티브로**(이미지 삽입 ✕) — 받는 사람이 수정할 수 있어야 한다.
- 기술적 함정 몇 가지: 색상 hex에 `#` 넣으면 파일 깨짐, 캔버스 크기(와이드 13.3×7.5인치) 먼저 설정, 불릿은 옵션으로 처리(문자 `•` 직접 입력 금지), 기본 차트는 밋밋하므로 라벨·값·팔레트·그리드 반드시 커스텀.

## ⑥ 파일 검증 + ⑦ 시각 QA — 3단계

1. **스키마 검증**: 파일이 PowerPoint에서 안 깨지는지 자동 검사.
2. **텍스트 QA**: 텍스트를 추출해 내용 누락·오타·플레이스홀더 잔존 확인.
3. **시각 QA (가장 중요)**: PPTX → PDF → 이미지로 렌더링해서 **전 슬라이드를 눈으로 확인**한다. 코드만 보면 "의도"를 보게 되고, 렌더링을 봐야 "실제"가 보인다.
   - 체크 항목: 텍스트 오버플로우(1순위), 요소 겹침, 출처와 본문 충돌, 간격 불균형, 저대비 텍스트, 여백 부족
   - 결함이 있는 슬라이드만 수정하고 재렌더 → 반복하지 않고 멈춘다.

## 디자인 규칙

### 팔레트
- **주제에 맞는 팔레트**를 고른다. 다른 주제 덱에 그대로 옮겨도 어울리면 선택이 안일한 것.
- **1개 지배색(60~70%) + 보조 1~2 + 액센트 1**. 모든 색을 균등하게 쓰지 않는다.
- **색에 의미를 부여하고 끝까지 유지**: 이번 덱은 코랄=AI 흡수/경고, 틸=인간 잔존/긍정, 네이비=중립/구조. 독자가 색만 보고 범주를 읽게 된다.
- 다크–라이트 샌드위치: 표지·클로징은 다크, 본문은 라이트.

### 타이포그래피
- 제목은 세리프(Cambria), 본문은 산세리프(Calibri) — 대비로 위계를 만든다.
- 크기 위계 고정: 슬라이드 제목 26pt+ 볼드 / 카드 헤더 14 볼드 / 본문 11.5~13 / 출처 9.5 이탤릭.
- 킥커(상단 소제목)는 소형 대문자+자간으로 섹션 내비게이션 역할.

### 레이아웃
- **모든 슬라이드에 시각 요소** — 텍스트만 있는 슬라이드 금지.
- **레이아웃 변주**: 3열 카드, 2×2 그리드, 차트+사이드카드, 대형 스탯 콜아웃, 폭이 줄어드는 래더(위계 표현). 같은 레이아웃 연속 반복 금지.
- 여백: 슬라이드 가장자리 0.5인치 이상, 블록 간 0.3인치 이상.
- 본문은 좌측 정렬(가운데 정렬은 제목만).

### 금지 사항
- 제목 밑 액센트 라인, 상하단 컬러 바, 사이드 스트라이프 — AI 생성 티가 나는 요소.
- 텍스트 오버플로우 상태로 납품.
- 기본 차트 스타일 그대로 사용(단일 시리즈에 범례, 진한 그리드, 라벨 없음).
- 크림/베이지 기본 배경 — 흰색 또는 브랜드 팔레트.

## 신뢰성 규칙 (내용 차원)

- **슬라이드마다 출처를 그 슬라이드에** 표기한다(맨 뒤 출처 모음만으로는 부족).
- 벤더·기업 발표 수치에는 **"self-reported" 플래그**를 슬라이드 위에 직접 단다.
- 추정치에는 `~`, 범위에는 범위를 그대로("+6~12%"), 단일 막대로 그릴 땐 "중간값 표시"를 각주로.
- 상관관계 연구는 인과로 서술하지 않는다.
- 반박·번복이 있었던 출처(예: METR 2026 재검토)는 원 수치와 함께 **번복 사실도 표기**한다.

## 요약: 품질을 만드는 5가지 습관

1. **단위 정의가 절반이다** — 무엇을 세는지(잡 vs 태스크) 먼저 정하면 리서치가 흩어지지 않는다.
2. **증거에 등급을 매겨라** — 모든 숫자가 동급이 아니다. 등급을 밝히는 것이 곧 신뢰다.
3. **반대 증거를 의무적으로 찾아라** — 카운터 신호가 있는 리포트가 강하다.
4. **제목을 주장문으로 써라** — 제목만 이어 읽어도 브리핑이 되게.
5. **렌더링을 눈으로 봐라** — 코드·텍스트 검토는 시각 QA를 대체하지 못한다.
