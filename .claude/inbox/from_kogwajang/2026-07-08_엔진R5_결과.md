## few-shot 관찰 (구현 전 필수 — v3/axis2_layouts/inbox/pdf_*)
`v3/axis2_layouts/inbox/`는 페이지가 PDF가 아니라 페이지별 JPEG(`000.jpg`...)로 이미 풀려 있어 Read로 직접 열람 가능했다. 6개 덱(`pdf_kpmg_kr_auto_navigator_2q_2026`, `pdf_kpmg_kr_global_ma_2026`, `pdf_a16z_state_of_crypto_2025`, `pdf_kpmg_kr_ces2026_preview`, `pdf_bond_usa_inc_revisited_2025`, `pdf_bond_our_new_world`)에서 8페이지를 Read로 열람했다.
1. 순수 "논증 도식"(2x2 포지셔닝 맵·피라미드·인과 사슬 자체)은 샘플링한 8페이지 중 단 한 장도 없었다 — 전부 막대·도넛·표·큰 숫자 같은 데이터 차트이거나 텍스트 블록+아이콘 그리드였다. 이건 오히려 DESIGN_R5 §0의 전제("기존 23종은 데이터 차트뿐, 논증 도식 공백")를 실물로 재확인해 준다.
2. 공통 여백 문법: 카드 상단 라벨 바(진한 단색) + 넉넉한 좌우 여백 + 차트 아래 `Source:`/`Note:` 소형 회색 캡션 한 줄. 액센트는 딱 1~2색(주 컬러 + 회색 뮤트), 다색 사용은 카테고리 범례가 있을 때만.
3. 타이포 밀도: 헤드라인 2줄 이내, 본문 불릿은 짧은 문장 3~5개, 숫자는 항상 큼직한 단독 볼드로 분리되어 있고 라벨과 섞어 쓰지 않음 — 이 원칙을 4종 렌더러의 값/라벨 분리(별도 `<text>` + `data-metric-id`)에 그대로 반영했다.
(PDF Read 자체는 문제없이 됐다 — "Read 안 됨" 상황은 발생하지 않았음을 밝혀둔다.)

## 구현
### 1. `pyramid`
- `series[0..]`의 `role` 필드(`claim`/`evidence`)로 층 구성. evidence 2~4단, 아래로 갈수록 넓어지는 사다리꼴 스택(`<polygon>`).
- claim = accent 단색 + 흰 글자, evidence = `color-mix(accent 12%)` 옅은 톤 + 잉크 글자 — swot_quad 선례(color-mix 기반, 테마 무관 안전) 그대로 채용.
- metric_id 붙은 evidence는 `_viz_series`가 이미 해석한 값을 `data-metric-id`로 노출(C6 authority 통과).

### 2. `causal_chain`
- flow(`_svg_flow`)와 같은 화살표+알약 노드 문법을 base로 하되, 각 링크(화살표) 아래 `evidence` 근거 캡션 슬롯을 추가.
- 노드 라벨은 인과 서술문이라 flow보다 길어서 `_wrap_text`로 최대 2줄 wrap 필수 — **1차 구현에서 wrap을 빠뜨려 4번째 노드 라벨이 캔버스 밖으로 잘리고 캡션 두 개가 겹쳐 붙는 버그를 데모 PDF 육안 검수에서 실측**, 노드 폭/좌표 여유·wrap 로직을 다시 짜서 수정. 수정 후 재렌더로 확인 완료(아래 "시각 QA" 참조).

### 3. `two_by_two`
- swot_quad 선례를 따라 `_viz_series`를 우회하고 `block.series`를 직접 읽음(x/y/emphasis는 일반 변환이 안 나르는 필드).
- 사분면 배경은 옅은 단일 톤(`color-mix(ink 4%)`), cross line 2개, `x_axis`/`y_axis` low/high 라벨은 회전 없이 네 모서리 바깥에 배치(회전 텍스트는 복잡도 대비 이득이 없어 배제 — ponytail: 필요해지면 그때 추가).
- 아이템은 좌표 매핑 후 emphasis 여부로 accent/muted 점 크기·색 분기.

### 4. `tradeoff`
- mirror_bars(수치 비교)와 달리 질적 대비이므로 막대가 아니라 좌/우 2열 불릿 리스트 + 중앙 "VS" 구분선.
- 좌측=accent, 우측=중립톤(`color-mix(ink 62%)`)으로 나눠 "어느 쪽이 옳다"는 가치판단 없이 대구만 세움. `metric_id` 있는 항목은 열 끝에 수치 배지로 표시.

### 공통 남발 방지 게이트
- `SUPPORTED_VIZ_CHART_TYPES` 4종 등록.
- `SUPPORTED_VIZ_SERIES_ROLES`에 `claim`/`evidence` 추가.
- 신설 `VIZ_CHARTS_WITHOUT_REQUIRED_METRIC`(swot_quad·fin_table·4종) — 정성 슬롯은 metric_id 미필수(swot_quad 선례 확장).
- 신설 `ARG_DIAGRAM_MIN_SLOTS` + 슬롯 미달 검사, 위반 메시지에 `ARG_DIAGRAM_THIN` 태그 삽입(grep 가능):
  - pyramid: evidence < 2
  - causal_chain: 노드 < 3
  - two_by_two: 아이템 < 3, 각 item의 x/y가 0~1 범위 밖이면 별도 위반
  - tradeoff: 좌/우 각 1개 미만이면 위반, `side`가 left/right 아니면 별도 위반
- 이 검사들은 기존 `_validate_viz_block` 안에 swot_quad/fin_table과 같은 자리에 추가 — 새 contract_id를 만들지 않고 기존 `C6` 우산 아래 재사용(같은 함수가 이미 chart별 분기를 하고 있어 이게 가장 짧은 diff였음).

## 반송 1R — tradeoff 보강 (2026-07-08)

본부 육안 검수(page-4.png 실측)에서 `_svg_tradeoff`가 "저울 대비 구도"가 아니라 "2단 불릿 목록 + 가운데 VS 칩"으로 읽힌다는 반송을 받아 `_svg_tradeoff`(render_deck.py 3153~3243행)만 보강했다.

- 좌우를 swot_quad 관례의 tint 패널(`<rect rx=14>`)로 묶고, `block.emphasis`("left"/"right", 옵션)가 있으면 그쪽만 accent 16% 틴트 + 상단 5px accent 바, 없으면 기존 관례(좌=accent 약한 틴트/우=중립)를 유지.
- 중앙 세로선을 패널 전체 높이로 늘리고 `var(--card)` 배경 + accent 테두리의 "VS" 원형 배지를 스파인 중앙에 얹어 도식의 등뼈로 세움. 항목별 `metric_id` 수치는 라벨과 같은 행에 정렬된 둥근 칩(`data-metric-id` 유지)으로 이동해 더는 붕 뜨지 않음.
- 항목 수가 적어도(데모 spec = 좌2/우1) 도식이 캔버스를 충분히 쓰도록 내용 영역 최소 높이(280)를 보장하고 행을 그 안에서 수직 중앙 정렬 — 반송 사유 #3(하단 40% 공백) 해소.
