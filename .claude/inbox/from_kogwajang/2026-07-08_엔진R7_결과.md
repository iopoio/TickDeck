### ① `factcheck_dump.py` 신설 (팩트체크 대조표)
- 스키마 실측: `_workspace/20260707_clo_report_r4/`를 read-only로 열어 확인 — `metric_registry`·`source_registry`는 06이 아니라 **02_verified.json 안에** 있음(06_deck_spec.json은 `metric_id` 참조만 갖고 값은 없음). 설계 문서가 "06 + registry"로만 적어놔서 실물 확인 없이 짐작했으면 틀렸을 지점.
- 페이지 content 트리를 재귀 순회해 `metric_id`(단수 키) / `metric_ids`(리스트 키)를 전부 수집 — content 블록 종류(`metric`/`metrics`/`viz` series/`viz` fin_table cells/annotation callout 등)를 일일이 나열하지 않고 키 기반 범용 워커 하나로 처리(신규 블록 타입이 생겨도 별도 분기 불필요).
- `page_no`는 `page_id`(`p05` 등)에서 숫자 파싱, `claim_context`는 `short_title` + 첫 `headline` 텍스트 조합.
- 출처: `metric_registry[id].source_ids[0]` → `source_registry`에서 `url` 또는 `local_path` 채움. `source_ids`가 비어 있으면(예: derived 메트릭) `source_missing: true`로 **표시**(숨기지 않음). registry에 아예 없는 metric_id는 `registry_missing`도 같이 표시.
- 같은 metric이 한 페이지에 두 번 나오면(차트 + 콜아웃 등) 1행으로 합침, 다른 페이지면 페이지마다 별도 행 — 설계 문서 규칙 그대로.
- stdout 요약: `rows: N` / `source_missing: N` / `json: <path>`.

### ② `external_review.py` — `--stage spec` 모드 추가 (기본값)
- `--stage` 인자 신설: `spec`(기본, R7 신규) / `html`(기존 동작 그대로 보존, 레거시 플래그).
- `extract_page_texts_from_spec()`: 06_deck_spec.json 페이지별로 `short_title` + 재귀 텍스트 워커(`text`/`term`/`def`/`label` 키 및 평문 리스트 요소 전부 수집 — text_table 행, bullets, columns, fin_table 셀 등 커버) + metric 값 텍스트(02_verified.json `metric_registry`에서 `"{label} {value}{unit} ({period})"` 형태로 해석)를 합쳐 페이지 텍스트를 구성.
- metric_id 추출은 `factcheck_dump.collect_metric_refs()`를 **재사용**(중복 구현 안 함) — 같은 디렉터리 sibling 모듈이라 `sys.path` 삽입 후 `import factcheck_dump`.
- `build_review_prompt()`(프롬프트 틀·5개 렌즈·출력 형식)는 완전히 그대로 재사용 — 텍스트 소스만 교체.
- `write_review_json()`을 해시 필드명 파라미터화(`deck_html_sha256` ↔ `deck_spec_sha256`) + `stage` 필드 추가. html 모드는 기존 `deck_html_sha256` 키·값 계산 방식 불변 — C9 계약(`contract_checks.py`가 `deck_html_sha256`만 읽음)과 호환.
- html 모드 회귀 없음: `--stage html`로 R4 deck.html 사본 dry-run 시 기존과 동일하게 `deck_html_sha256` 키로 정상 기록됨(아래 raw 참조).
