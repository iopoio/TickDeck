# 시니어 리서치 애널리스트의 트렌드 리포트 자동화 방법론 (실행 규칙)

이 규칙은 코드 기반/AI 보조 워크플로우가 트렌드 리포트를 생산할 때 준수해야 할 결정론적 지침입니다. 추상적 지시는 배제하고, 임계값(Threshold)과 조건문(IF-THEN) 형태로 명문화합니다.

---

## 1. 자료 수집 (Data Collection)

### 1.1 소스 계층화 (Source Tiering)
*   **Tier 1 (채택 우선순위 1):** 정부/공공기관 통계(통계청, OECD), 글로벌 컨설팅펌(Big 4, McKinsey, BCG), 전문 리서치 기관(Gartner, IDC). 단, 원본 보고서(PDF/보도자료)에 직접 접근해야 함.
*   **Tier 2 (채택 우선순위 2):** 1차 자료를 인용한 주요 언론사(블룸버그, FT, 한국경제 등) 기사, 업계 리더의 공식 발언(컨퍼런스 키노트).
*   **Tier 3 (거부/참고용):** 개인 블로그, 검증되지 않은 업체 보도자료, 다른 2차 자료를 링크 없이 인용한 매체.
*   **규칙 (IF Tier 3 인용 발견):** 반드시 원문(Tier 1/2)을 역추적. 원문 미발견 시 해당 수치/주장은 폐기.

### 1.2 교차확인 및 검증 규칙 (Cross-Validation Rule)
*   **트렌드 채택 임계값:** 특정 주장이 2개 이상의 독립적인 Tier 1/2 소스에서 언급되어야 '마이너 트렌드'로 등재.
*   **하드 넘버(Hard Number) 채택 임계값:** 수치 1개 인용 시, 최소 2개의 독립적 출처가 오차범위 10% 이내로 일치해야 함.
*   **IF 충돌 발생 (모순된 수치):** 지역(예: 글로벌 vs 한국), 표본(예: B2B vs B2C), 조사 시점(연도)이 다른지 먼저 검증. 차이가 발생한 '조건'을 리포트에 명시.

### 1.3 수치 인용 전 체크리스트
1.  `[ ]` 원문(PDF/URL) 직접 확인 여부
2.  `[ ]` 조사 연도 및 발행 연도 확인 (3년 이상 경과 데이터는 "과거 데이터"로 태깅)
3.  `[ ]` 표본 크기(N) 및 조사 방법론(설문 vs 관측) 확인
4.  `[ ]` 2차 매체의 어견해석이 끼어들었는지 원문 대조

## 2. 내용 구조화 (Content Structuring)

### 2.1 CED (Claim-Evidence-Data) 매핑 시스템
모든 수집 정보는 3열 매트릭스로 분해되어야 함.
*   **Column A (Claim):** "AI 도입이 X 산업의 중간 유통 구조를 붕괴시킨다."
*   **Column B (Evidence):** 주요 3개사의 직접 거래 플랫폼 출시, 도매업체 매출 하락.
*   **Column C (Data):** 2024년 대비 2025년 도매업체 평균 매출 -12%, 플랫폼 직거래 비중 38%->54% (출처: Tier 1).
*   **규칙:** Column C가 비어있으면 Column A는 리포트에서 삭제.

### 2.2 우선순위 결정 (Impact vs. Probability Matrix)
*   모든 클러스터를 2x2 매트릭스로 배치.
    *   **High Impact / High Probability:** 리포트의 핵심 챕터(Thesis)로 배치.
    *   **High Impact / Low Probability:** '와일드카드' 또는 '리스크' 섹션으로 배치.
    *   **Low Impact / High Probability:** 부록 또는 인포그래픽용 데이터로만 사용.
    *   **Low Impact / Low Probability:** 폐기.

### 2.3 정보 단위 결정 (1 슬라이드/섹션 원칙)
*   1개 섹션 = 1개의 핵심 메시지(Headline) + 2개의 데이터 포인트 + 1개의 질적 인용(Expert Quote).
*   **규칙:** 한 단락에 수치가 4개 이상 들어가면, 테이블이나 차트로 시각화 전환. 텍스트 밀도 임계값 초과로 간주.

## 3. 스토리·구성 (Story & Composition)

### 3.1 관통 명제 (Thesis) 설정
*   **규칙:** "X 산업은 Y 트렌드로 변화하고 있다" 수준의 서술 금지.
*   **포맷:** "[거시적 변인]이 [특정 기술/행동]과 결합하면서, [산업의 특정 구조]를 [어떤 형태]로 재편할 것이다." (So-What Test 통과 필수)

### 3.2 챕터 흐름 프레임워크 (ODCC)
1.  **Opening (거시적 변화):** 인구통계, 거시경제, 기술 패러다임 변화. 독자의 Pain-point 정의.
2.  **Development (힘의 충돌):** 트렌드를 주도하는 플레이어와 요인. 여기서 주요 데이터(증가율, 투자액)를 배치.
3.  **Convergence (변곤점):** 개별 트렌드가 어떻게 교차하여 새로운 비즈니스 모델을 만드는가.
4.  **Closing (액션/대응):** 기업/투자자/정책입안자가 내일부터 취해야 할 3가지 행동 지침.

### 3.3 내러티브와 데이터의 배치 법칙
*   **도입부:** 추상적 내러티브로 문제의식 제기.
*   **전개부:** 객관적 데이터로 내러티브를 지지(데이터가 '왜' 그런지 설명하는 것은 내러티브의 역할).
*   **결론부:** 데이터를 넘어 미래 시나리오(내러티브)로 수렴.

## 4. 출처 신뢰성 표기 및 약한 데이터 처리

### 4.1 출처 표기 스탠다드
*   모든 수치 옆에는 인라인 출처 태그 필수: `[출처: 기관명, 보고서명, 발행월, p. OO]`
*   차트 하단에는 조사조건 필수 표기: `(대상: N=2,000 / 20~30대 직장인 / 한국 / 2025년 3월)`

### 4.2 약한 데이터 처리 규칙 (Weak Data Handling)
*   IF 표본 크기 N < 300 OR 비공식 인터뷰:
    *   수치를 배제하고, "일부 전문가들은 ~한 가능성을 제시한다" 수준의 정성적 인사이트로만 격하.
*   IF 데이터의 연도가 3년 이상 경과:
    *   최신 트렌드로 포장 금지, "과거 베이스라인"으로 명시.

### 4.3 '그럴듯한 함정' 회피 (Source Laundering Check)
*   "맥킨지 리포트에 따르면..." 이라는 문장 발견 시 경고.
*   해당 리포트가 진짜 맥킨지 것인지, 아니면 AI가 환각한 것이거나 영세 업체가 쓴 자료를 빙자한 것인지 아카이브 검색 필수.

## 5. 안티패턴 (Amateur/AI Slop 회피법)

### 5.1 신호 탐지 및 규칙
1.  **AI 슬롭 신호:** "AI는 모든 것을 혁신할 것입니다", "퍼스널라이제이션이 중요해집니다" (구체성 0).
    *   **회피 규칙:** 추상 명사(AI, ESG, 효율성) 금지. "생성형 AI 기반 요약 기능", "탄소 배출권 거래 시스템 연동" 등 물리적/기술적 실체로 치환.
2.  **아마추어 신호:** 모든 트렌드가 "성장"하고 "기회"임. 역풍이나 실패 사례 없음.
    *   **회피 규칙:** 모든 트렌드 챕터 내에 1개 이상의 '저항 요인(Counter-trend) 또는 한계점' 서술 필수.
3.  **AI 슬롭 신호:** 문맥상 완벽하지만 수치가 소수점 둘째 자리까지 맞거나, 출처 URL이 404 에러.
    *   **회피 규칙:** 수치는 반올림하여 처리(3.14% -> 3.1%). 모든 URL은 HTTP 상태코드 200 확인 필수.

## 6. 너만의 독창적 방법 (Unique Methodology)

이 방법론은 일반적인 워크플로우가 놓치는 깊이 있는 인사이트를 강제로 도출하기 위한 장치입니다.

### 6.1 네거티브 스페이스 트렌드 맵핑 (Negative Space Trend Mapping)
*   **개념:** 사람들이 "무엇이 뜬다"고 말하는 것을 찾는 것을 넘어, "무엇이 사라지고 있거나, 무엇이 거론되지 않는가"를 역추적하여 미래를 본다.
*   **실행 규칙:**
    1.  최근 2년간 Tier 1 기업들의 '실패한 프로젝트' 또는 '철수한 사업'을 크롤링.
    2.  2. 이 철수의 공통 원인을 분석.
    3.  예: 모두가 "초개인화 AI"를 트렌드라 할 때, "초개인화 모델의 콜드 스타트 문제로 인해 B2B SaaS 기업 3개사가 해당 라인을 폐기함"을 발견.
    4.  리포트에 "초개인화의 역설: 데이터 부족으로 인한 하이브리드 모델로의 회귀" 트렌드를 추가. (단순 유행 추종이 아닌 구조적 한계 도출)

### 6.2 히스토리컬 아날로그 매트릭스 (Historical Analog Matrix)
*   **개념:** 2026년의 신기술 트렌드를 과거의 특정 시점과 완벽히 동일시하는 것은 위험하지만, '수요 곡선의 형태'나 '규제 대응 패턴'은 반복된다.
*   **실행 규칙:**
    1.  현재 트렌드 키워드(예: 자율주행 택시 상용화)를 입력하면, 과거 역사적 사건(예: 2010년대 초반 공유경제 Uber의 첫 등장)을 강제 매핑.
    2.  당시 1년, 3년, 5년 뒤 규제와 소비자 인식이 어떻게 변했는지 데이터를 끌어와 현재 트렌드의 타임라인 예측에 적용.
    3.  이를 통해 "자율주행 상용화 후 2년 차에는 보험료 산정 구조 분쟁이 발생할 것" 등 타 리포트가 놓치는 후속 이벤트를 예측.

### 6.3 즉각적 실행 질문 (Actionable Threshold Trigger)
*   **개념:** 트렌드 리포트는 "재미있는 읽을거리"가 아닌 "의사결정 도구"여야 한다.
*   **실행 규칙:** 각 트렌드의 끝에 `[Trigger Point]`를 부록으로 제시.
    *   형식: "만약 [특정 지표]가 [특정 수치]에 도달한다면, [특정 부서/역할]은 [특정 행동]을 개시해야 한다."
    *   예: `[Trigger Point] 글로벌 배터리 탄소 배출 규제(CBAM) 본격 과세 전환 시(2026년 Q3 예상), 공급망 관리팀은 중국 내 2차 배터리 벤더 비중을 현재 대비 15% 축소하는 리스크 헤지 시나리오를 가동할 것.`
