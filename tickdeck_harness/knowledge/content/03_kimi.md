 아래는 트렌드 리포트 생산 워크플로우를 **코드화 가능한 규칙 세트(Rule-Set)** 로 명문화한 것이다. 추상적 원칙이 아닌, **임계값(Threshold)·플래그(Flag)·체크리스트(Checklist)·의사결정 트리** 형태로 작성했다. 다른 모델이 이를 호스팅해 자동화 파이프라인을 구축할 수 있도록 설계했다.

# 1. 자료 수집 (Ingestion & Verification)

## 1.1 소스 분류 및 가중치
| 분류 | 예시 | 가중치 | 채택 규칙 |
|---|---|---|---|
| **1차** | 규제 filings(SEC/금융위), 기업 실적발표(earnings call transcript), 특허청 문헌, 고용/채용 데이터, 원자료 통계청 DB | 0.4 | **필수 1개 이상** 포함 시 섹션 채택 가능 |
| **2차** | McKinsey Global Institute, BCG, CB Insights, Euromonitor, Gartner(Critical only), IDC, IMF WEO, 한국은행, 관련 학회 논문 | 0.35 | **2개 이상** 독립 기관 확인 시 ‘확증’으로 처리 |
| **3차** | 언론, 뉴스레터, 블로그, 팟캐스트 | 0.25 | **단독 인용 금지**. 1차/2차를 인용한 3차만 사용 가능 |
| **금지** | 후원 콘텐츠(스폰서드 표기 없는), press release 원문 그대로, 생성형 AI 이미지 속 수치, 날짜 없는 인포그래픽, Quora/블라인드 익명 글 | — | 수집 즉시 `FLAG::UNRELIABLE` |

## 1.2 검색 프로토콜
```text
QUERY_BUILD(keyword):
  cluster_1 = 기술/트렌드 핵심 어휘 (예: "generative AI")
  cluster_2 = 산업/시장 수식어 (예: "manufacturing cost structure")
  cluster_3 = 결과/영향 어휘 (예: "labor productivity" OR "capex")
  TIME_BOUND = (현재 연도 - 24개월) ~ 현재
  LANG_PRIORITY = ["en", "ko", "zh"]  # 영문 1순위, 국내 리포트 시 한국어 필수 추가
  return AND(clust_1, cluster_2, cluster_3) + TIME_BOUND
```

## 1.3 교차확인 (Cross-Reference) 규칙
- **RULE_1.3.1**: 동일 수치를 **2개 이상의 독립 소스**에서 확인하지 못하면 본문 인용 불가. 단, 1차 원자료(국가 통계, 기업 10-K)는 단독 인용 가능.
- **RULE_1.3.2**: 수치 차이가 **±15% 이상**일 경우, `FLAG::DISCREPANCY`를 생성하고 양쪽의 **조사 조건(Method)** 을 메타데이터에 기록. 해석 없이는 양쪽을 동시에 인용하지 않는다.
- **RULE_1.3.3**: 인용 전 **5-Step 원문 추적 체인** 수행.
  1. 원문(PDF/HTML) 다운로드
  2. Perma.cc 또는 archive.today 아카이브
  3. 수치가 등장하는 페이지/단락 스크린샷 저장
  4. Methodology(조사기간, 샘플, 지역, 환율 기준) 추출
  5. 발행기관의 이해관계(후원·컨설팅 계약·투자은행 리포트면 투자의견 여부) 태깅

## 1.4 수치 1개를 인용하기 전 체크리스트
- [ ] **원문 접근 가능** (페이월이라도 기관명·보고서명·페이지 특정 가능)
- [ ] **발행 연도·분기** 명기됨
- [ ] **지역 Scope** 명기됨 (Global vs US vs Korea)
- [ ] **샘플/조사 조건** 명기됨 (n=?, online panel?, phone?)
- [ ] **환율/단위** 명기됨 (USD? KRW? nominal?)
- [ ] **기관의 Conflict of Interest** 1줄 이내 요약 가능

# 2. 내용 구조화 (Structuring)

## 2.1 주장-근거 매핑 (CEMS: Claim-Evidence-Metric-Source)
모든 정보 단위는 아래 5열로 정규화한다.

| Claim (주장) | Evidence (근거 유형) | Metric (수치) | Source (출처) | Limitation (한계) |
|---|---|---|---|---|
| "X 산업의 자동화 투자가 가속화된다" | 고용 데이터 + 특허 트렌드 | "협동로봇 관련 채용공고 YoY +34%" | LinkedIn Economic Graph, 2024Q2 | LinkedIn 샘플 편향 존재, 제조업 집중 |

- **RULE_2.1.1**: Metric이 비어 있으면 해당 Claim은 `STATUS::OPINION`으로 분류, 메인 섹션 배치 불가. 서브 섹션 or 삭제.
- **RULE_2.1.2**: Limitation이 명시되지 않은 Row는 `FLAG::UNAUDITED` 처리.

## 2.2 주제 클러스터링 (Topic Clustering)
- **RULE_2.2.1**: **3개 이상의 독립 출처**에서 언급된 주제만 ‘클러스터’로 인정. 2개 이하은 `CLUSTER::FRAGILE`, 메인 ToC 제외.
- **RULE_2.2.2**: 키워드 공기(co-occurrence) 기반 클러스터링. 예: "AI"와 "전력소비"가 3개 이상 2차 보고서에서 동시에 등장하면 서브 클러스터 `"AI-Energy Nexus"` 생성.
- **RULE_2.2.3**: 중복 클레임 발견 시 우선순위 알고리즘 적용:
  ```python
  priority_score = (recency_weight * 출처_신선도) + 
                   (primary_weight * 1차자료_여부) + 
                   (sample_weight * log(샘플_크기))
  # 최고 점수 1개만 메인, 나머지는 각주로 전락
  ```

## 2.3 우선순위: IMPACT × CERTAINTY 매트릭스
| | 높은 확실성 | 낮은 확실성 |
|---|---|---|
| **높은 임팩트** | **메인 섹션** (Ch.1~3) | **시나리오 섹션** (Ch.4) |
| **낮은 임팩트** | **서브/박스** (Call-out) | **삭제** |

- **THRESHOLD**: Impact 4점 이상 × Certainty 4점 이상(5점 만점) → 메인. 3×3 이하 → 삭제.
- **RULE_2.3.1**: Certainty는 1차 자료 존재(+1), 2개 이상 교차확인(+1), Methodology 투명(+1), 발행기관 중립(+1), 최근 12개월 이내(+1) 로 산출.

## 2.4 한 슬라이드/섹션 정보 단위
- **1 Slide = 1 INSight**
  - **Assertion** (1문장): "무엇이 변하는가"
  - **Evidence** (1~2개 수치/차트): "얼마나 변하는가"
  - **Implication** (1문장): "독자가 무엇을 해야 하는가"
- **1 Section** = 3~5개 INSight. 6개 이상 시 분할, 2개 이하면 인접 섹션과 병합.

# 3. 스토리·구성 (Narrative Architecture)

## 3.1 관통 명제 (Thesis) 설정
- **RULE_3.1.1**: Thesis는 반드시 **"A는 B를 C한다"** 형태의 원인-결과 서술이어야 한다. 추상적 제목 금지.
  - ❌ "2026 X산업 트렌드 10선"
  - ✅ "X산업의 단가 하락이 공급망 재편을 촉발하고, 이는 Tier-2 업체의 M&A 서막이 될 것이다"
- **RULE_3.1.2**: Thesis 확정 전 **"So What?" 3회 질문**을 통과해야 한다.
  1. 이 트렌드가 누구에게 이익/손실인가?
  2. 그 이익/손실의 규모는 얼마인가?
  3. 타임라인은 언제인가?
  - 1개라도 답이 없으면 Thesis는 가설로만 남기고, Ch.1에서 탐색 문제로 전환.

## 3.2 챕터 흐름: TENSION → DIAGNOSIS → MECHANISM → SCENARIOS → CONVERGENCE → ACTION
| 순서 | 기능 | 데이터 vs 내러티브 비율 | 필수 요소 |
|---|---|---|---|
| **Opener** | 기존 믿음 vs 새로운 현상의 괴리(Tension) 설정 | 내러티브 7 : 데이터 3 | "모두가 알고 있던 사실은 이제 틀렸다" 식의 구체적 수치 대비 |
| **Diagnosis** | 현재 상태 수량화 | 데이터 8 : 내러티브 2 | 시장 규모,渗遠률, 투자액, 1개의 히트맵/차트 |
| **Mechanism** | 왜 일어나는가 (구조적 동인) | 내러티브 6 : 데이터 4 | 2~3개의 동인을 인과 체인으로 연결 (A→B→C) |
| **Scenarios** | 전개 방향 분기 | 데이터 5 : 내러티브 5 | 낙관/기저/비관 3개 시나리오 + 각각의 트리거 이벤트 2개 |
| **Convergence** | 전략적 함의 수렴 | 내러티브 7 : 데이터 3 | "결국 기업은 OO를 해야 한다" 1문장 |
| **Closing** | 실행 가능한 첫걸음 | 내러티브 8 : 데이터 2 | 30·60·90일 로드맵 or 3가지 '오늘 할 수 있는 행동' |

- **RULE_3.2.1**: 챕터 전환 시 **논리 접속사 필수** ("따라서", "그러나", "반대로", "결과적으로"). 없으면 `FLAG::DISCONTINUITY`.

## 3.3 데이터-내러티브 배치 규칙
- **RULE_3.3.1**: 차트/표는 **반드시 1문장 해석 문장**을 동반한다. "그림 1을 보면 알 수 있듯" 금지. → "2020년 대비 2024년 고객 획득 비용이 2.3배 증가했으므로, DTC 전략의 경제성이 붕괴했다."
- **RULE_3.3.2**: 내러티브가 '틀(Framework)'을 제공하고, 데이터가 '틀 안을 채운다'. 데이터만 나열한 슬라이드(`FLAG::DUMP`)는 재구성 의무.
- **RULE_3.3.3**: **강한 수치는 인트로/클로징**에 배치. 중간 해석은 메커니즘 설명에 사용.

# 4. 출처 신뢰성 (Provenance & Annotation)

## 4.1 인용 표기 규칙
모든 수치는 본문 하단 또는 해당 슬라이드 하단에 아래 형식으로 표기.

```text
[기관/저자], 《보고서명/논문명》, 연도, p.페이지.
조건: [지역/샘플/기간/방법론].
아카이브: [Perma.cc/원문 URL].
태그: [1차/2차/3차], [투자의견 포함 여부], [후원 여부].
```

## 4.2 약한 데이터 처리 프로토콜
| 취약성 유형 | 본문 표현 규칙 | 색상/태그 |
|---|---|---|
| 샘플 n<100 | "일부 조사에 따르면(샘플 87명)..." | `TYPE::SMALL_SAMPLE` |
| 연도 미상(n.d.) | "시점 불명의 조사에서..." | `TYPE::UNDATED` |
| 특정 기업 후원 | "A사 후원 조사에 따르면..." | `TYPE::SPONSORED` |
| 비동기 조사(phone+online 혼합) | "방식 상이한 조사들을 종합하면..." | `TYPE::MIXED_MODE` |
| 예측치(Forecast) 원천 불명 | **인용 금지** | `FLAG::NO_FORECAST` |

- **RULE_4.2.1**: 약한 데이터는 메인 Assertion의 근거로 사용 불가. 서브 근거 or 부연 설명 용도로만 사용.

## 4.3 "그럴듯하지만 검증 안 됨" 함정 회피 체크
수치 인용 전 아래 5개 질문에 **모두 Yes**여야 한다.
- [ ] **원문 존재**: 해당 수치가 적힌 문서의 실제 PDF/HTML을 내가 열어보았는가?
- [ ] **메소놀로지 페이지 존재**: 원문에 '조사 방법' 페이지/섹션이 있는가?
- [ ] **발행기관 도메인 신뢰**: 도메인 연령 2년 이상 or 기관 등록 확인 가능?
- [ ] **아카이브 완료**: Wayback Machine 또는 Perma.cc에 저장했는가?
- [ ] **반대 입장 탐색**: 이 수치와 **모순되는** 다른 연구/기사를 1건 이상 찾아보았는가?

# 5. 안티패턴 (Anti-Patterns)

| 신호 (Amateur/AI-Slop Signal) | 자동 탐지 키워드/패턴 | 회피법 (Repair Rule) |
|---|---|---|
| **추상 조언** | "~해야 한다", "~를 고려해야 한다" | 수치 없는 조언문 자동 삭제. 대체: "~는 매출의 X%를 차지하며, 이는 Y년 대비 Δ% 증다" |
| **정량 없는 전망** | "성장할 것이다", "확대될 전망이다" | "CAGR A%~B% (출처), 가정: [구체적 시장조건]" |
| **주어 없는 문장** | "많은 기업들이 ~하고 있다" | "상위 10개 기업 중 7개(출처)가 2024년 내 ~를 도입했다" |
| **레고 블록 나열** | AI 한 장, ESG 한 장, 메타버스 한 장… 교차 없음 | 교차 매트릭스 필수: AI×ESG, 규제×공급망 등 2차원 분석 |
| **출처: 구글** | "출처: 인터넷", "출처: Google" | 원문 URL or 보고서명+페이지. 불가 시 인용 삭제. |
| **미래시제 남발** | "~할 것이다" 반복 | 시나리오 기반 서술: "낙관 시 [수치], 기저 시 [수치], 비관 시 [수치]" |
| **챗GPT형 서두** | " rapid pace of technological change...", "ever-evolving landscape" | 1문장 내 구체적 수치 등장. 예: "2024년 상반기 X기술 특허 출원이 3,400건으로 전년 동기 대비 120% 급증했다." |

- **RULE_5.1**: 최종 검수 시 **Ctrl+F**로 아래 단어 자동 검색 후 삭제/수정: `landscape`, `paradigm shift` (비수치화 시), `game changer` (근거 없을 시), `in today's world`, `delve`, `tapestry`.

# 6. 독창적 방법론: "역산·틈새·실패" 트라이앵글

다른 모델이 놓치기 쉬운 고유 기법을 아래 4가지로 명문화한다.

## 6.1 증거의 역산 (Inversion of Evidence Searching)
- **규칙**: 가설을 설정한 후, **가설의 역(NOT A)**을 먼저 검색한다.
  - 예: "생성형 AI가 개발자 생산성을 40% 높인다"는 클레임 → **"AI coding productivity no improvement"**, **"developer productivity flat after copilot"** 등을 먼저 검색.
- **임계값**: 역검색 결과 1건 이상 발견 시, 해당 논거를 **메인 클레임에 병렬 배치**하고 "제한적 반론" 섹션에 2줄 의무 기술. Confirmation Bias 차단.

## 6.2 TTA 역추산 (Time-To-Adoption Backcasting)
- **규칙**: 현재 트렌드의 성숙도를 과거 유사 기술 도입 곡선(스마트폰 2007-2012, 클라우드 2010-2015)과 비교하지 않는다. 대신 **현재 시점의 투자·특허·채용 데이터**를 입력 변수로 하여 도입 속도 함수 v(t)를 추정.
- **적용**: 현재 v(t)가 과거 스마트폰 대비 2배라면, TTA는 과거의 1/2로 추정. 이를 통해 "과거 패턴 매칭"이 아닌 "동적 도입 모델"로 시나리오 작성.

## 6.3 카운터펙추얼 슬롯 (Counterfactual Slot)
- **규칙**: 각 주요 섹션(챕터) 마지막에 **"만약 이 트렌드가 2026년까지 실패/지연된다면, 그 결정적 원인은 무엇인가?"** 를 3줄 이내로 의무 삽입.
- **효과**: 단순한 낙관론을 필터링하고, 리포트의 내구도(지속 가능한 분석)를 높인다. AI가 생성하기 쉬운 '단방향 예측'을 방지.

## 6.4 언어 간 로컬 라그 분석 (Inter-Language Lag Mining)
- **규칙**: 영문 1차 보고서를 베이스로 삼되, **한국어/일본어/중국어 보고서**를 반드시 1건 이상 수집하여 "글로벌 균형(Global Equilibrium)"과 "로컬 균형(Local Equilibrium)"의 **시차(Time Lag)**를 측정한다.
  - 예: 글로벌에서는 "EV 전환"이 기정사실화되었으나, 한국어 보고서에서는 "수소·하이브리드 논의"가 여전히 30% 이상 비중 → 이 **틈새(Gap)**가 전략적 기회 포착 지점.
- **임계값**: 로컬 자료 2개 이상에서 글로벌과 다른 어조(낙관/비관)가 20%p 이상 차이 날 경우, 별도 `BOX::Regional Variance` 생성.

## 6.5 디버깅 프롬프트 자동 실행 (Adversarial Self-Review)
- **규칙**: 리포트 초안 완성 후, 아래 3인칭 페르소나로 자체 반박을 생성한다.
  ```text
  PERSONA_1: "당신은 해당 산업의 15년차 임원이다. 이 리포트에서 가장 허술한 근거 3가지를 지적하라."
  PERSONA_2: "당신은 경쟁사 리서치 애널리스트다. 이 리포트의 Thesis를 뒤집는 반론을 200자로 써라."
  PERSONA_3: "당신은 학계의 엄격한 심사자다. Methodology가 약한 인용을 모두 찾아내라."
  ```
- **수정 임계값**: 2개 이상의 페르소나가 동일 지적을 하면 해당 섹션은 **재작성 의무**.

```text
[자료 수집]

   ↓
[서사 구성]
   ↓
THESIS 설정 → "So What?" 3회 통과? → 챕터 흐름(TENSION→ACTION) 배분
   ↓
[출처 처리]
   ↓
WEAK_DATA 태깅 → 아카이브 Perma.cc → 5질문 Yes? → FINAL ANNOTATION
```
