## 언제 쓰나

- 주제: 회사소개서·제안서·포트폴리오 덱 — 실적과 사례로 신뢰를 쌓아 계약으로 미는 문서
- 청중: 잠재 고객·발주처 심사자 — "이 팀에 맡겨도 되나"를 15장 안에 판단하는 사람
- 정서: 겸손 없는 자신감 + 근거 즉납 — 단정하되 바로 옆에 숫자가 서 있는 톤

## 산출물 계약 (엄수)

- 파일: `pages/pXX.html` — **단독 완결 HTML** (외부 리소스 0 · CSS 인라인 `<style>` · JS 없음)
- 스테이지: `.stage` 고정 **1280×720px**, `overflow:hidden`. 콘텐츠가 720 안에 다 들어와야 함 — 넘칠 것 같으면 요소를 줄인다 (폰트 축소보다 블록 수 축소 우선)
- body: `background:#DDE1E7; display:flex; align-items:center; justify-content:center;` 가운데 스테이지 1개
- 폰트 스택: `"Pretendard Variable",Pretendard,-apple-system,"Apple SD Gothic Neo","Noto Sans KR","Malgun Gothic",sans-serif`

## 골격 7레버 (필수 문법 — 제안서·소개서 장르 한정)

1. **프롤로그 아치** (15장+ 필수): 표지 → 대형 스탯 훅 1장("26년·5조원"급 회사 한 줄 근거) → 고객 증거 1장 → 다크 브레이크 한 문장 → 그다음에야 목차. 목차 전에 회사의 한 문장 서사를 끝낸다 — "표지→목차 직행" 금지
2. **페이지 연결 제목**: 앞 장 제목이 쉼표로 끝나고("~실행력을 바탕으로,") 다음 장 제목이 술어로 받는다("수많은 고객의 성장을 이끌어냈습니다"). 연속 2장까지만·각 장 자립 가독 유지 조건
3. **도트 리더 스탯 행**: 라벨 ···점선 리더··· 초대형 액센트 숫자. 라벨-값 연결이 시선 유도. 스탯 4개를 2×2로
4. **이정표 콜라우드 차트**: 시계열 막대를 과거=그레이 → 근래=옅은 액센트 → 현재=진한 액센트로 톤 진행 + "N억 돌파" 점선 마커 + 누적(잉크 칩) vs 현재(액센트 말풍선) 이중 강조
5. **사례 페이지 표준 골격** (사례 다건이면 기본값): 좌 = 캠페인 유형(소)·브랜드명(대)·한 줄 목표·BUSINESS/PERIOD 메타 / 우 = PROJECT 요약 + 실행 불릿 3~4 / 하단 = 실물 산출물 그리드. 매 사례 같은 템플릿 반복 — 일관성이 곧 실력 증명
6. **독자 질문 훅**: 부제 자리에 독자의 질문을 선제("특정 업종 경험이 있는 대행사를 찾고 계신가요?") — 덱당 1~2회만
7. **어미 스위치**: 이 장르는 "~합니다" 경어 완결 단정 — 겸손 없이 단정하되 **반드시 같은 장이나 직후 장에 근거 스탯이 따라온다**. 근거 없는 단정은 장르 불문 금지 (트렌드 리포트의 "~다" 평서·명사형과 구분)

## 콘텐츠 계약 (위반 = 실격)

- **수치는 briefs/pXX.json의 metrics 값만** 사용 — value·unit·scope 그대로. 수치 발명·반올림 변경·단위 생략 금지. 쓰지 않는 metric은 생략 OK
- note의 `==키워드==`는 `<b class="hl">키워드</b>`(얹은 세트의 액센트)로 변환
- footnote(정직 각주)는 반드시 유지 — 얹은 세트의 각주 카드 물성으로, "ⓘ" 머리
- 출처 푸터: brief의 sources에서 그 페이지에 실제 쓴 출처 기관명만
- 문체: 이 장르는 위 7번 어미 스위치 우선("~합니다" 단정)·불릿 끝 마침표 없음·이모지 0·한자 0·brief 원문 워딩 우선 (다듬기 금지 — 원문 그대로 하류 전달)

## 페이지 다양성 (단조 금지)

- 직전·직후 페이지와 같은 실루엣 금지 — 단 사례 페이지 연속 구간은 예외 (표준 골격 반복이 의도)
- 프롤로그 아치의 스탯 훅·다크 브레이크가 비정형 몫을 채운다
- 목차·출처·outro는 조용하게 — 장식 최소, 타이포 위주
