# R5 설계 — 논증 전용 도식 (취향 잔여 1호 해소) (2026-07-08)

> 배경: 7/8 geo_seed 런 아쉬움 ③ "맞춤 시각화 부재 — 차트 전부 템플릿, 논증 전용 도식 없음" = 취향 잔여 1호. GLM 5.2 교차에서도 1순위 지목(수렴)으로 우선순위 승격. 후추님 7/8 "계속하자" 방향 확인.

## 0. 문제 정의 (왜 기존 23종으로 안 되나)

기존 도식형 차트(flow·arrow_flow·hub_cycle·gap_map·swot_quad)는 **모양이 먼저 있고 내용을 끼워 넣는** 템플릿이다. 컨설팅 정본의 도식은 반대 — **페이지의 논증 구조가 모양을 결정**한다 (주장을 근거가 떠받치고, 인과가 사슬로 이어지고, 선택지가 축 위에 놓인다). 이 층이 비어 있어서 주장 페이지가 텍스트 블록+범용 차트로만 조립됨 = "조금"의 정체 중 하나.

## 1. 접근 선택 — B안 (논증 어휘 4종 신설)

| 안 | 내용 | 판정 |
|---|---|---|
| A. Mermaid 컴파일 | Mermaid→SVG 외부 도구 | 기각 — 신규 의존성·DS 스타일 불일치·계약(C6) 밖 |
| **B. 논증 어휘 차트 4종** | 기존 `_CHART_RENDERERS` 패턴으로 논증 구조 차트 추가 | **채택** — 무의존성·계약 그대로·page-planner가 고르는 기존 흐름 재사용 |
| C. 범용 논증 컴파일러 | argument JSON→레이아웃 엔진 (GLM 제안 원형) | 보류 — B로 80% 커버 후 부족하면 승격 |

근거: 컨설팅 도식의 어휘는 사실상 유한하다. "맞춤" 느낌은 기하학의 무한함이 아니라 **내용이 구조 슬롯에 정확히 맵핑되는 것**에서 나온다. (ponytail: B의 천장 = 비정형 논증 구조. 그때 C로 승격.)

## 2. 신설 차트 4종 (argument family)

공통: 기존 viz 블록 스키마 재사용. 수치 슬롯은 `metric_id` 연결 → C6 출처 계약·source_caption 층 그대로 탄다.

1. **`pyramid`** — 주장 1 + 근거 겹(2~4단). 밀도 2겹 룰(7/8 page-planner)의 시각 짝. series = [{claim}, {evidence, metric_id?}, ...] 층위 필드.
2. **`causal_chain`** — A→B→C 인과 사슬. arrow_flow와 차이 = 각 링크에 근거 캡션 슬롯(metric_id). "왜 이어지는가"가 그림에 박힘.
3. **`two_by_two`** — 축 2개 + 아이템 (x,y) 배치. market-research 장르 필수품(플레이어 포지셔닝). swot_quad와 차이 = 축 라벨이 자유 변수·아이템이 좌표를 가짐.
4. **`tradeoff`** — 좌우 저울(얻는 것 vs 잃는 것·A안 vs B안). ARCH-versus 아키타입 궁합.

## 3. 남발 방지 게이트

- 논증 도식은 **실제 논증 구조가 spec에 있을 때만** — pyramid의 근거 슬롯이 본문 불릿 복붙이면 장식이다. qa-reviewer "팩토리 티 판정"에 1줄 추가: *논증 도식의 슬롯 내용이 본문과 중복이면(요약이 아니라 복사) 지적*.
- contract: 슬롯 최소 개수(pyramid 근거≥2·causal_chain 노드≥3·two_by_two 아이템≥3) 미달 = 위반 (빈약한 도식이 페이지 주인공 되는 것 방지).

## 4. 구현 분담

- 클차장 (직접): 본 설계 + page-planner.md("주장 페이지에서 근거 2겹 이상이면 pyramid/causal_chain 우선 고려"·아키타입 궁합표) + qa-reviewer.md 1줄.
- **렌더러 4종 + contract + 테스트 + 데모: 소넷 배치** (코과장 한도 소진·7/8 후추님 "소넷으로 처리" 흐름. 클차장 스펙·diff 검수·실렌더 QA는 그대로 의무).

### 5b. 도구 재검토 (7/8 후추님 "예쁨 검토" 지시 후속)

- toolify "Mermaid 대안" 10종(Eraser·Edraw·Diagrimo·Cloudairy·ChartDB 등) = 사람용 SaaS 앱 — 렌더 파이프라인 편입 불가(API 비용·네트워크 의존·DS 못 입음·한글 통제 불가). 전부 기각.
- **D2(terrastruct) = 유일한 진짜 경쟁자** — 코드 기반 중 최고 미관(테마 30종·폰트 임베드·SVG). 그러나 노드-엣지 그래프 언어라 자동 레이아웃이 강점인데, 본 4종은 **구도 고정 도식**(2x2 좌표·저울 대칭)이라 불일치 + 우리 DS 입히려면 커스텀 테마 작업 중복. **이번엔 기각, C안 승격 시 백엔드 1순위 후보로 기록.**
- 자체 SVG의 예쁨 근거 = DS 규율(타이포·정렬·여백·의미색) + 블라인드 비교 게이트(실전 PDF 17건 대조)가 판정. 기존 23종이 같은 방식으로 R4 블라인드 통과 = 실증.
- **few-shot 의무 (신설)**: 소넷 구현 전 `v3/axis2_layouts/inbox/pdf_*`에서 논증 도식 실물 페이지 2~3장을 Read로 열어 여백·타이포 밀도를 참조한다. 빈손으로 그리지 않는다.
