## 0. 리뷰 전 발견한 사실 2개 (문서들이 서로 모름)

1. **엔진 1콜화는 "계획"이 아니라 이미 씨앗이 있고, 1회 완주 실측까지 있다.**
   `.claude/skills/deck-harness/scripts/run_deck.sh` = `claude -p` 헤드리스 1콜 + 계약 게이트 재확인 + `total_cost_usd` 자동 기록. `_workspace/_cost_log.jsonl`에 실측 1건 존재:
   `20260705_clo_market · $16.15 · 벽시계 4,791초(약 80분)` [실측]
   → PRODUCT_ROADMAP Phase 1("수동→스크립트")과 PRD_PRODUCT §6("없는 것: 엔진 1콜화")은 반쯤 스테일. 갭은 "1콜을 만드는 것"이 아니라 **"1콜이 사람 개입 0으로 반복 성공하느냐"**다.

2. **PRD_PRODUCT §2의 속도표는 옛 실측(7/5 run, 810k tok·에이전트 35분) 기준이고, 최신 실측(7/25 senior_market)과 모순된다.**
   senior_market(15장): 서브에이전트 1,462k tok · 에이전트 순차 약 2시간 [실측]. 810k→1,462k 증가 원인 = 장수 증가(10→15) + 그 사이 추가된 품질 게이트(7.4 프리리뷰·7.55 맞춤법·3b 팩트체크·Loop L). **"질 상수" 축이 원가·시간을 계속 올리는 구조** — 속도 로드맵이 이걸 반영 안 하면 매번 목표 미달로 보인다.

## 1. 기술 리스크 Top 5

### R1. 엔진 1콜화의 실체 — 어떤 런타임으로 무인 실행하나

**실체**: 현 엔진 = Claude Code 세션 + `.claude/agents/` 9종 + skills + 로컬 스크립트(render_deck.py 등) + 외부 의존(codex CLI·gemini wrapper·신야 venv·Jina·WebSearch). `run_deck.sh`가 이걸 `claude -p --dangerously-skip-permissions`로 감쌌고 1회 완주했다 [실측].

**선택지**:
| 안 | 내용 | 공수 | 품질 유지 | 판정 |
|---|---|---|---|---|
| (a) 헤드리스 유지 (`claude -p` → Claude Agent SDK) | 기존 agents/skills **그대로** 재사용. run_deck.sh가 이미 이 안 | 소 (스파이크 1주) | 최고 — 프롬프트·게이트 무변경 | **추천** |
| (b) Messages API 직접 오케스트레이션 재구현 (Python) | 단계별 API 콜 + tool 루프 자작 | 대 (3주+) | 위험 — agent .md 프롬프트 + 오케스트레이터 암묵 판단 이식 중 드리프트, 이중 유지보수 | 기각 (지금은) |
| (c) Managed Agents (Anthropic 호스팅) | 서버가 루프+샌드박스 호스팅 | 중 | 미지수 — 로컬 의존(신야 venv·mypdf 코퍼스·chrome 캡처) 이식 필요 · beta | 보류 (규모 확장 때 재검토) |

**추천 (a)의 근거**: 질=v4 그대로가 확정이면, 질을 만드는 실체(agent md·skill 워크플로·계약 스크립트)를 안 건드리는 경로가 유일하게 품질 리스크 0에 가깝다. 이미 1회 완주 실측이 있다. 재구현(b)은 "속도·원가를 위해 질 실체를 옮겨 적는" 일이라 질 상수 원칙과 정면 충돌.

**(a)의 숨은 조건 3개 (문서에 없음)**:
1. **과금 전환**: 현재 run은 Claude 구독 위에서 돌았다(`total_cost_usd`는 API 환산치). 유료 SaaS 백엔드를 소비자 구독으로 돌리는 건 약관·한도(주간 상한) 양면에서 부적합 [판단] → 서비스 런은 API 키 과금으로. $16 실측이 이미 API 환산가라 원가 모델 자체는 유효.
2. **codex CLI 의존 제거**: 7.4 프리리뷰·3층 외부리뷰가 `codex exec`(ChatGPT 구독 CLI)에 의존 — 서비스 런타임에 못 넣는다. 3층을 "타 모델 API 1콜"(gemini wrapper는 API라 유지 가능 + codex 몫은 별도 opus 페르소나 콜)로 재정의 필요.
3. **신야 경유 재결정**: collector가 공개 발행물 대량 소화를 신야(중국 모델·격리)에 위임한다. 상용 서비스에서 **고객 seed 자료**가 이 경로에 섞이면 보안 룰·고객 신뢰 양쪽 사고. 서비스 모드에선 신야 경유 차단 또는 "공개 URL만" 코드 강제 필요.

### R2. 무인 품질 게이트 — 지금 사람(클차장)이 서 있는 자리 7곳

**실체**: SKILL.md 4층 검토 중 코드 게이트(run_contracts·qa_lint·spellcheck·C6·FIT)는 이미 무인. 사람 판단이 박힌 곳 = ① 2층 총괄 게이트(통째 판정) ② qa_lint WARN 트리아지(오탐 약 절반) ③ spellcheck WARN 확인 ④ 7.4 프리리뷰 치명 지적 트리아지 ⑤ 3층 외부리뷰 트리아지 ⑥ 7.7 best-of-N 선택 ⑦ 4층 시각 QA(PDF 직접 읽기 — 단 qa-reviewer 에이전트가 PDF Read로 visual_verdict 기록하는 배선은 이미 존재).

**정직한 지점**: 이 7곳의 사람 판단도 "v4 질"의 일부다. 완전 자동 대치 = 어느 정도의 질 드리프트를 수반한다. "질 상수 + 완전 무인"은 검증 없이는 동시에 주장 못 한다.

**선택지**: (a) 판단 게이트를 opus 에이전트 판정 + 실패 시 1회 재시도 + 저신뢰 플래그로 대치, 플래그 건만 사람 큐 (b) S0~S1 저볼륨 구간은 **무인 생성 + 발송 전 사람 스팟체크(비동기)** — 사용자 체감은 여전히 딸깍(버튼→알림), 내부만 human-in-loop (c) 전 게이트 즉시 자동화.

**추천**: (b)→(a) 순차. 출시선(S1)에선 (b)가 맞다 — 덱 몇 개/일 수준에서 스팟체크는 몇 분 비용이고, 그 판정 로그가 (a)의 자동 판정기를 학습·검증하는 데이터가 된다. (c)는 "무인 run 연속 통과 실측" 없이 가면 7/6 채택 실패보다 나쁜 품질 사고로 돌아온다.

### R3. webtoslide 백엔드 접합 — 골격은 재사용, 파이프는 교체

**실체**: 두 엔진 괴리(CLAUDE.md 명시). 옛 파이프 = URL→crawler→Gemini 3단→python-pptx→PPTX 편집(EditorPage)→다운로드, 잡 길이 분 단위. 새 파이프 = 주제+자료→v4 하네스→HTML/PDF, 잡 길이 30~90분.

**불일치 목록 (전부 접합 작업 대상)**:
- 입력 스키마: URL 1개 → 주제·seed 자료(PDF 업로드)·맥락 텍스트
- 출력: PPTX+편집 플로우 → HTML/PDF 다운로드(+PPTX는 pptx_export 옵션). **EditorPage(9.3K)는 폐기** — PPTX 중간 편집은 v4 출력과 무관
- 잡 수명: Celery 설정 전면 재튜닝 필요 — `soft_time_limit`≥2h·`acks_late`·visibility timeout·진행 이벤트·실패 시 토큰 환불 시점(부분 실패 = _workspace 잔존물 정리 포함)
- **워커 런타임이 무겁다**: claude CLI + headless chrome(capture_deck) + python venv + (신야 venv) → Railway/Vercel 워커에 안 올라간다. 초기 워커 = **Mac mini 셀프호스트**가 현실. NEXT_STEPS의 "프로덕션 배포(Railway 등)" 항목은 API 서버·프론트만 해당, 생성 워커는 별도.
- 게이트: SaaS 층은 7/8 동결 선언 상태 — 접합 착수 전 후추님 동결 해제 결재 필요.

**판정**: 골격(FastAPI·OAuth·토큰 ledger·Celery 배선·React 셸)은 재사용 가치 충분. 단 "얹으면 됨" 아니고 **새 task + 새 job 모델 + 프론트 2페이지 개조**가 실작업. §4 표 참조.

**바닥 계산 [추론]**: 7단 스테이지 간 의존은 직렬이 구조다(수집→검증→분석→스토리→페이지→디자인→QA). 스테이지 내 병렬 + 다이어트를 다 먹어도 크리티컬 패스 합 ≈ 50~70분. **"몇 분"(S2 표기)은 스테이지 통합 없이는 불가능하고, 스테이지 통합은 질 아키텍처(계약·권한 분리) 훼손 = 질 상수 위반.** "십몇 분"도 S1(검수루프 제거만)로는 근거 없음 — 최신 실측이 반박.

**그러나**: PRD_PRODUCT §2 각주가 스스로 인정하듯 wedge(전략기획자·데드라인 기반)는 비동기라 **90분도 딸깍 성립**("며칠→90분"). 결론 = 속도표의 숫자 라벨만 고치면 로드맵 논리는 산다. 재정의안은 §2 판정표.

### R5. 원가 — 실측 $16/덱, 원가 < 가격은 성립 전망, 단 n=1

**실측**: $16.15/덱 (10장·7/5·결함수정 루프 포함이라 상한 쪽) [실측].
**교차 추정 [추론]**: senior_market 1,462k tok을 PRD §14 모델 매핑(opus=intake·analyst·editorial·planner 516k / sonnet=collector·verifier·designer 946k)에 현행 단가(Opus 4.8 $5/$25 · Sonnet $3/$15 / MTok, 입출력 85:15 가정)로 곱하면 서브에이전트만 약 $9 + 오케스트레이터·미실시 게이트(3b 팩트체크·3층)까지 **$15~25/덱 구간**. 실측 $16과 정합.

**절감 지점 (효과 순)**:
1. **프롬프트 캐싱**: 에이전트 md(designer 18.9K·planner 18.7K)+writing-standard+workspace JSON 반복 재독이 입력의 대부분 — 캐시 읽기 0.1×. 헤드리스 Claude 런타임은 자동 적용되나, 커스텀 오케스트레이션으로 갈 경우 직접 설계 필요. [추론: 입력측 30~60% 절감]
2. **재수집·개정 루프 감소**: designer 개정 루프가 옛 run에서 390k — qa_lint·프리리뷰 같은 "렌더 전 조기 게이트"가 이미 그 방향. 루프 1회 절감 = $2~4.
3. **라우팅 미세화**: verifier의 코드 검사 비중 확대(모델 콜 축소)·기계적 단계 haiku($1/$5) 강등 — 품질 게이트(미달 시 승격)가 있어 안전.
4. **Batches API(50% 할인)**: tool-use 루프엔 부적합, 단발 콜 단계(7.6 폴리시 패스·팩트체크 대조)만 해당 — 부분 절감.

**판정**: B2B wedge 가격(덱당 수만 원대 또는 구독)이면 원가 $10~25로 마진 성립 [추론]. 철칙("원가<가격") 위반 위험은 낮으나, **n=1이라 스파이크로 n≥3 확보가 가격 확정의 전제.** 주의: "질 상수" 게이트가 늘 때마다 원가가 오르는 구조(810k→1,462k가 증거)이므로 cost_note 관례(런당 기록)를 계속 유지할 것.

## 2. S0~S3 타당성 판정표

| 단계 | PRD 표기 | 판정 | 근거·조건 |
|---|---|---|---|
| S0 비동기 (버튼→알림) | 잡큐 래핑 | **조건부 가능** | 잡큐 자체는 며칠 거리(기존 Celery). 진짜 전제 2개: ① 무인 완주 반복 안정성(현재 실측 1/1 — 표본 부족) ② SaaS 동결 해제 결재. R2의 (b)안(내부 스팟체크)과 병행하면 출시 가능 |
| S1 "~십몇 분" | 검수루프 제거 | **안 됨 (숫자 스테일)** → 재정의 권고 | 최신 실측: 무인 1콜 80분·순차 2h. 검수루프 제거만으론 십몇 분 불가. **재정의: S1 = 무인 완주 + 벽시계 ≤90분 = 출시선.** wedge 논리("며칠→초안"의 단축)는 90분으로도 성립 — PRD 자신의 감내선 각주와 일치 |
| S2 "~몇 분" | 병렬화 | **몇 분 = 안 됨 / 30~60분 = 조건부 가능** | 스테이지 내 병렬(collector 팬아웃·verifier 청크·designer 분할) + 컨텍스트 다이어트로 30~60분 [추론]. 7단 직렬 크리티컬 패스가 구조적 바닥 — "몇 분"은 스테이지 통합 = 질 상수 위반이라 기각 |
| S3 라우팅·캐싱 | 분 단위 | **원가 레버로는 가능, 속도 레버로는 미미** | 캐싱·배치·라우팅은 $ 절감(30~50% [추론])이 본질. 지연 단축 효과는 부차적. "분 단위" 표기는 삭제하고 **S3 = 원가 절감 + 동시 처리량(잡 병렬)**로 목적 재기술 권고 |

한 줄: **속도 축의 진짜 로드맵은 "2.5h→90분(무인)→40분(병렬)→상수 유지·원가 하강"이다.** 십몇 분·몇 분 라벨은 최신 실측과 모순되므로 PRD_PRODUCT §2 표만 갱신하면 나머지 논리는 그대로 산다.

## 3. 개발 계획 (1인·회복기 · 스파이크 우선 · 날짜 없음)

원칙: 제일 불확실한 것부터 작게 찌른다. 순서 = 무인 완주 신뢰도 → 무인 QA → 속도 → 접합 → 원가 → 결제. 1~3단계는 backend/frontend를 안 건드리므로 SaaS 동결과 충돌 없음.

| # | 단계 | 기간 | 내용 | 완료 기준 (측정 가능) |
|---|---|---|---|---|
| 0 | 전제 결재 (후추님·병행) | - | ① SaaS 동결 해제 시점 ② Phase 0 쇼케이스 채택 신호(만들 이유 게이트) ③ 신야 경유 서비스 정책 | 결재 기록 |
| 1 | **스파이크 A: 무인 완주 신뢰도** | 1주 | run_deck.sh로 wedge형 요청 3회 연속, 사람 개입 0. 실패 유형(게이트 미달·루프 폭주·외부 의존 실패) 분류 | 3/3 산출(deck.html+pdf+계약 0건) 또는 실패 유형 목록 확보. cost_log 3행 추가 |
| 1' | **스파이크 B: API 과금 실측** (A와 병행) | 3~5일 | 동일 run을 API 키 과금으로 1회 — 구독 밖에서 도는지 + 원가 확정 | API 키 런 1회 완주 + `total_cost_usd` 실측치 |
| 2 | **무인 게이트 v1** | 1~2주 | R2의 7곳: 코드 게이트 유지·판단 게이트 opus 판정+저신뢰 플래그·codex 의존 제거(3층 재정의)·발송 전 스팟체크 큐 | 무인 run의 07_qa_report에 전 게이트 판정 기록 + 후추님 스팟 판정 "감내 가능" 3연속 |
| 3 | **병렬화 1차 + 컨텍스트 다이어트** | 1~2주 | collector 팬아웃 3~5·verifier 청크·analyst 렌즈 병렬·page-planner 입력 다이어트 | 15장급 벽시계 ≤60~90분 실측 (질 게이트 통과 유지 — 행동 회귀 eval 기준선 대조) |
| 4 | **백엔드 접합** (동결 해제 후) | 2주 | 새 Celery task(run_deck subprocess)+job 모델+진행 이벤트+HTML/PDF 저장·다운로드. HomePage 입력 폼(주제+PDF)·LoadingPage 단계 개조. EditorPage 제외. 워커 = Mac mini | 로그인→입력→비동기 생성→알림→다운로드 E2E 1회 + 워커 강제 kill 시 토큰 환불 확인 |
| 5 | **원가 제어** | 1~2주 | 캐시 적중 확인·라우팅 재점검·cost_log n≥10·가격 초안 | 덱당 원가 확정(평균±분산) + 원가<가격 판정 문서화 |
| 6 | **결제 + 클로즈드 베타** | 2~3주 | 기존 로드맵 Phase 5~6 그대로 (PG 연동 = 신규 작업) | 유료 결제 1건 처리 + 베타 사용자 덱 1개 전달 |

총 8~12주 [추론]. kill 게이트는 기존 PRD 그대로: Phase 0 신호 약함 / 원가>가격 구조적 / 회복기 페이스 초과 시 중단. 스파이크 A가 실패(3회 중 반복 미완주)하면 2단계보다 먼저 실패 유형 근본 수정 — 그게 이 계획에서 유일하게 순서를 바꿀 수 있는 사건.

## 4. 기존 자산 재사용 vs 재작성 판정표

| 자산 | 판정 | 근거 |
|---|---|---|
| FastAPI 골격 (auth·user·토큰 라우터·models·alembic) | **재사용** | 잡 제출/조회 API만 신규. 검증된 OAuth·JWT 흐름 버릴 이유 없음 |
| Google OAuth | **재사용 그대로** | 프로덕션 redirect URI 등록만 잔여 (기존 NEXT_STEPS 항목) |
| 토큰 결제/환불 ledger (`lock_tx_id`+autoretry) | **재사용 + 단가 재설계** | 환불 배선 우수. 단 1토큰=1덱 크레딧으로 의미 변경(원가 $16 vs 옛 URL덱). 실 결제(PG)는 원래 미구현 = 신규 |
| Celery + Redis | **재사용 + 재튜닝** | 배선 재사용. 장시간 잡 설정(acks_late·soft_time_limit≥2h·prefetch 1·진행 이벤트) 전면 손질. Mac 워커라 Windows solo pool 제약은 소멸 |
| React 셸 (Login·Callback·잔액·Done) | **재사용** | 로그인·다운로드 흐름 유지 |
| HomePage / LoadingPage | **개조** | 입력 폼(URL→주제+PDF+맥락)·진행 단계(v4 9단계) 교체 |
| EditorPage (PPTX 중간 편집) | **폐기** | v4 출력(HTML/PDF)과 무관한 옛 파이프 전용 |
| Gemini 3단 파이프라인 + crawler + quality.py | **은퇴·도장** | v4가 완전 대체. `feedback_stale_doc_status_stamp` 관례로 status 도장 |
| shared/pptx_builder.py | **은퇴** | PPTX 출력은 v4 `pptx_export.py`가 담당 |
| v4 하네스 (agents·skills·contracts·render) | **그대로 = 제품 코어** | 수정 최소화가 곧 질 상수 |
| run_deck.sh + _cost_log | **그대로 = 스파이크 A 도구** | 이미 1콜+원가 기록 구현 완료 |

인프라 주의 1줄: 생성 워커는 claude CLI·headless chrome·로컬 venv 의존 → 당분간 **Mac mini 셀프호스트 확정**, API 서버·프론트만 클라우드 후보. 단일 Mac = 동시 처리량 상한(순차 1~2잡)이라 베타 규모까지만 유효, 그 이상은 R1(c) Managed Agents 재검토 지점.
