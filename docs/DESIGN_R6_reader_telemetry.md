# R6 설계 — 독자 텔레메트리 (2026-07-08)

> 배경: 취향 장부 7/8 [코드 대기] "독자 텔레메트리 — 비용 ~0·복리 자산". 게이트 재설계(PLAN_SEED §6)의 "블로그 인바운드 계측 병행"의 실체. 후추님 7/8 "계속하자" 트랙.

## 0. 원칙 — 새 인프라 0

펩핀치 블로그에 GA4(gtag)가 이미 가동 중. 덱 HTML에 바닐라 JS 스니펫 하나로 GA4 이벤트를 쏘고, 판독은 GA Events에서 (좋아요 카운터와 같은 관례). 서버·DB·외부 서비스 추가 없음.

## 1. 발동 조건 (기본 OFF — 납품 덱 보호)

- deck_spec meta `"telemetry": {"ga_id": "G-..."}` 가 있을 때만 스니펫 삽입. **기본 = 없음 = 계측 0.**
- 이유: CLO·수주 납품 덱에 추적 코드가 몰래 들어가면 신뢰 자산("감사 가능한 신뢰") 훼손. 쇼케이스/블로그 게시 런에서만 명시적으로 켠다.
- PDF 출력은 JS 미작동이라 무관. 데모·내부 런도 meta 없으니 무관.

## 2. 이벤트 3종 (GA4 커스텀 이벤트)

| 이벤트 | 파라미터 | 잡는 것 |
|---|---|---|
| `deck_page` | deck_id, page_no, dwell_bucket(3s/10s/30s/60s+) | 페이지별 체류 — IntersectionObserver(가시 50%+) + visibilitychange. 이탈 지점 = 마지막 deck_page |
| `deck_source_click` | deck_id, page_no, url(도메인만) | 출처 링크 클릭 — "감사 가능한 신뢰"가 실제 소비되는지 |
| `deck_read_end` | deck_id, max_page, total_pages | 완독률 — pagehide 시 sendBeacon |

- deck_id = run_id. dwell은 원초 대신 버킷(카디널리티 절약).
- 활용: page-planner 사전확률 갱신 입력(어떤 페이지 유형에서 이탈하나) + 게이트 판정 보조(반응 0의 4가설 중 ②가치 가설 판별 재료).

## 3. 구현 범위

- `render_deck.py`: meta.telemetry 있으면 `</body>` 앞에 gtag 로더 + 스니펫(~60줄, 인라인) 삽입. 없으면 출력 불변.
- 게이트: 없음 (측정 코드에 계약 불요). 단 **회귀 보호 테스트 2개** — ①meta 없을 때 출력에 gtag 문자열 0 ②meta 있을 때 이벤트 3종 문자열 존재.
- 분담: 설계 = 클차장 / 구현·테스트 = 소넷 / diff·데모 검수 = 클차장.
