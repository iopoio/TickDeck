## 1. 타이포 위계

- **제목 = 짧은 명사구 반복**: "Dashboard Data" "KPI Data Statistic Dashboard" "Dashboard Overview" 등 동일 문구를 전 슬라이드 상단에 반복(2·3·6·7·8/8). 제목이 콘텐츠가 아니라 **머릿글/브랜드 라벨** 역할.
- **2단 제목 색 대비**(2/8, 5·7): "KPI Data Statistic"(민트) + "Dashboard"(먹) 처럼 한 제목을 두 색으로 쪼갬. 강조어만 accent, 나머지 ink.
- **위계는 3단 고정**: ① 상단 제목(중대·볼드) ② 카드/섹션 소제목(작은 볼드, 종종 accent) ③ 본문(회색 muted, 8~10pt급 lorem). 본문은 거의 항상 "채움용 회색 덩어리"로 낮게 눌림.
- **숫자가 최상위 타이포**: KPI 수치(789K, $154,55, 68,214, 76%)가 제목보다 크거나 대등한 급으로 조판됨(8/8). 숫자 = 슬라이드의 실제 헤드라인.
- **산세리프 단일 패밀리**. 세리프 전무. 굵기 대비(Bold 수치 vs Regular 라벨)로만 위계 조절.
- 라벨류(축·범례·단위)는 아주 작은 대문자/회색으로 최하위 배치.

## 2. 그리드·컴포지션

- **카드 모듈 격자가 기본 골격**(8/8): 슬라이드를 2~6개 카드로 타일링. 카드 = 흰(라이트)/반투명 다크. 한 슬라이드 = 여러 위젯의 콜라주.
- **"대시보드 UI 흉내" 크롬**(2/8, 3·2): 슬라이드 콘텐츠를 통째로 흰 카드에 담고 상단에 검색바+창 컨트롤(···) 을 그려 실제 앱 화면처럼 위장. 이 패밀리만의 독특한 메타포.
- **좌측 세로 레일/탭**(2/8, 7·8): 왼쪽에 세로 네비게이션(아이콘 목록 or 세로 라벨 탭)을 두고 우측을 대시보드 본체로. 8은 "Task A/Mega Deal/Service Q" 사이드바까지.
- **좌: 텍스트·KPI / 우: 차트** 의 비대칭 2분할이 단일 위젯 슬라이드의 기본형(6/8).
- **상단 KPI 스트립 + 하단 차트** 의 상하 2단(6/8): 위에 숫자 카드 3~5개 나열, 아래 큰 차트 하나.
- 여백보다 **밀도 우선**. 특히 8(master)·6은 한 슬라이드에 위젯 6~10개를 꽉 채움. 미니멀 패밀리와 정반대.

## 3. 차트·데이터 화법 (이 패밀리 핵심)

### 3-1. 등장 차트 종류 (실측 빈도)
- **도넛/링(progress ring 포함)** — 8/8. 이 패밀리의 대표 마크. 중앙에 큰 % 또는 값(23%, 50%, 65%, 70%). 단일 값 게이지형과 다세그먼트 파이형 둘 다.
- **세로 막대(bar/column)** — 8/8. 월별/카테고리 비교. 라운드 톱 캡이 흔함.
- **가로 막대(진행바/랭킹)** — 7/8. Data A/B/C 옆에 % 채움바. KPI 리스트의 기본 표현.
- **꺾은선(line, 다계열 겹침)** — 8/8. 2~3개 라인 교차. 마커 점 강조.
- **면적(area, 그라데이션 채움)** — 7/8. 라인 아래를 accent→투명 그라데이션으로 채운 트래픽/트렌드형.
- **게이지(반원/원형 speedometer)** — 4/8 (1·5·6·8). 위험도/달성률.
- **파이(3D 입체 포함)** — 3/8 (4·8). 4·8은 3D 파이가 개별 버릇.
- **퍼널(역삼각 단계)** — 3/8 (6·7 "Income Funnel"·8).
- **불릿/스택 막대, waterfall(3)** — 산발적.
- 세계지도 위 데이터 핀 — 2/8 (1·8).

### 3-2. KPI 카드 문법 (패밀리 시그니처)
- **[큰 숫자 + 델타 + 라벨]** 3요소 카드가 표준 단위(8/8). 예: `+86,214 / Total User`, `$450,5 / Value 01 47%`.
- **델타 색코딩**: 증가 accent/그린, 감소 레드(-94,0 / -20%)를 색으로 즉시 구분(5·6·8).
- **아이콘 배지**: 카드 좌상단에 원형 아이콘(트위터/인스타/화살표/타깃) 을 붙여 지표 정체성 부여(6/8).
- **KPI를 도넛/미니바와 합체**: 숫자 카드 옆에 작은 진행 도넛·미니 스파크라인을 붙여 "값+추세" 동시 전달(7/8).
- **KPI 스트립**: 색이 다른 카드 3~5개를 가로로 나열(78%/90%/35%…), 카드마다 배경 accent 다르게(3·2·5).

### 3-3. 데이터 화법 태도
- **단일 지표를 크게, 맥락은 작게**: 하나의 히어로 수치를 도넛/빅넘버로 키우고 주변에 보조 위젯 배치.
- **색 = 계열 구분자**: 막대/라인/도넛 세그먼트를 팔레트 2~3색으로 순환(범례 최소화, 색으로 읽게 함).
- 차트에 **격자선은 옅게/최소화**, 축 라벨은 회색 소형. 차트가 "장식된 위젯"으로 보이도록 크롬을 정리.
- 그라데이션 채움(도넛 링·area)이 데이터 표현에 적극 사용됨 — 특히 1·4·7.

## 4. 장식 어휘

- **원형 아이콘 배지**(8/8): 지표/카드 앞 원 안 라인아이콘. 소셜·화살표·타깃·톱니.
- **알약(pill) 태그/버튼**(7/8): "See More" "Choice 01" "14 Day" "Visit Now" "2024" 등 라운드 캡슐 라벨.
- **진행바/채움바**(7/8): 가는 트랙 + accent 채움. KPI 옆 상시.
- **델타 화살표/삼각형**(6/8): ▲▼ + 증감 수치.
- **그라데이션 오브**(1·4·7): 파스텔 다색 그라데이션 도넛/블롭.
- **다크에서 네온 글로우**(1·5): accent 링·바에 발광 처리.
- 개별: "브라우저 창 크롬"(2·3), 좌측 세로 텍스트 탭(7), 사이드 네비 레일(8).

## 5. 컬러 운용

- **1 accent + 1 보조 accent + 중성(먹/회색/흰) 구조**가 기본(8/8). 팔레트 색상은 아이템마다 다름:
  - 1: 파스텔 멀티 그라데이션(핑크·라임·시안) on 다크
  - 2: 블루 단색 + 그레이 / 3: 틸+라임그린 / 4: 퍼플+옐로+시안(3색)
  - 5: 틸+오렌지 / 6: 블루+퍼플+라임 / 7: 민트+핑크(2색) / 8: 틸+레드+라이트블루
- **의미 색코딩**: 그린/accent=증가·양호, 레드=감소·위험(5·6·8). 순수 장식색과 구분됨.
- **라이트 6 / 다크 2**. 라이트는 흰 카드 on 옅은 배경, 다크는 반투명 카드 on 먹배경.
- 채도 높은 accent를 **작은 면적에만**(카드 헤더·바·도넛), 큰 면적은 중성으로. → 데이터가 튀어 보이는 위계.
- 2~3색 순환 팔레트로 다계열 차트를 색만으로 구분(범례 의존 최소).

## 6. 공통 문법 vs 개별 버릇

### 공통 (과반 5+/8)
1. 도넛/링 + 막대 + 라인 3종 세트가 전 아이템 반복 (8/8)
2. [큰 숫자 + 델타 + 라벨] KPI 카드가 기본 콘텐츠 단위 (8/8)
3. 카드 모듈 격자로 슬라이드를 위젯 콜라주화 (8/8)
4. 숫자를 제목급으로 키우는 "숫자=헤드라인" 조판 (8/8)
5. 1+1 accent + 중성 3색 구조 & 색으로 계열/의미 구분 (8/8)
6. 원형 아이콘 배지 + 알약 태그 + 진행바 장식 세트 (7/8)
7. 좌 텍스트·KPI / 우 차트 비대칭 분할 (6/8)
8. 증감 색코딩(그린 up / 레드 down) (6/8)
9. area 그라데이션 채움 트렌드 차트 (7/8)

### 개별 버릇 (1~2/8)
- "브라우저 앱 창" 크롬(검색바+창 컨트롤)으로 대시보드 UI 흉내 — 2·3(2/8)
- 좌측 세로 텍스트 탭 / 사이드 네비 레일 — 7·8(2/8)
- 3D 입체 파이 — 4·8(2/8)
- 세계지도 데이터 핀 — 1·8(2/8)
- 다크 네온 글로우 — 1·5(2/8)
- 파스텔 멀티 그라데이션 오브 — 1(1/8, 가장 독특)

## 7. TickDeck 엔진 시사점 (data_mono 대비)

1. **같은 뼈대**: data_mono의 "숫자=헤드라인 · 계기판/스펙시트 문법 · 방안지 지면"은 이 패밀리 관찰과 정확히 일치. 숫자를 제목급으로 키우고 격자 지면에 위젯을 얹는 태도는 검증됨 — 파일럿2 방향이 리퍼런스로 뒷받침된다.
2. **차트 커버리지 갭**: 리퍼런스 3대장은 **도넛(8/8)·막대·라인**인데 현 `_CHART_RENDERERS`엔 donut·gauge·funnel은 있으나 **일반 다계열 line/bar/area가 없다**(before_after·dumbbell·rising_columns 등 서사형 위주). 이 패밀리를 재현하려면 겹친 line·그라데이션 area·가로 진행바 렌더러 보강이 1순위.
3. **KPI 카드 = 명시 블록으로 승격**: [큰 숫자+델타+라벨+미니추세] 3~4요소 카드가 8/8 공통 단위인데 엔진엔 `big_number`만 있음. 델타 색코딩(그린 up/레드 down)과 미니 스파크라인/도넛 합체 카드를 하나의 KPI 블록으로 만들면 이 패밀리를 곧장 커버.
4. **data_mono 단색 vs 리퍼런스 2~3색 순환**: 모노 시스템은 accent+accent2 2색인데 리퍼런스는 계열 구분에 2~3색 순환을 상시 사용. 다계열 차트에서 t3~t5 톤을 계열색으로 순환시키는 규칙(색=범례 대체)을 명시하면 밀도 높은 대시보드 슬라이드가 가능.
5. **밀도 옵션**: 리퍼런스는 여백보다 밀도(6·8은 위젯 6~10개). data_mono가 기본 저밀도라면, "대시보드 조밀 레이아웃"을 별도 layout으로 두어 KPI 스트립+대형 차트 상하 2단 배치를 지원할 여지가 있음.
