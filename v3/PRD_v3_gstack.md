## Problem Statement
낯선 분야 조사 데이터를 설득 덱으로. **핵심 함정 = 양식이 적으면 매번 똑같은 덱.** 딥리서치가 차별이어도 양식이 N개 고정이면 무의미하다.

## What Makes This Cool
- **딥리서치**: 근거·출처 종합 (후추님이 "가끔" 하던 깊은 디깅을 매번·진실주의).
- **양식 무한 성장**: 양식 라이브러리가 계속 학습·확장 → 같은 주제도 매번 다른 덱.
- 후추님 고유 스타일 + 새 양식(envato·기타) 계속 흡수.

## Premises (office-hours에서 교정됨 — 이게 PRD_v3와 갈린 지점)
1. 핵심 차별 = **딥리서치 + 후추님 스타일 양식** (큐레이션 아님 — PRD_v3 정정). envato는 빈 양식 채운 임시.
2. 재사용 = 후추님 본인이 계속 활용 (1회성 X).
3. **양식 지속 학습·확장이 1급 시민** (적으면 매번 동일·후추님 통찰).
4. 진실주의 = 후추님 작업 방식(근거·출처 명시). Gamma 비교는 부적절(본부 오류 인정).
5. 중국 모델 = 비용절감용·대체 많음(Gemini·Claude·Codex)·단일 의존 리스크 X.

## Approaches Considered
- A. 딥리서치 + 후추님 스타일 템플릿(minimal) — ❌ **양식 적어 매번 동일**(후추님 거부).
- B. 후추님 스타일 학습 엔진 — 부분(후추님 덱만·확장 부족).
- C. 반자동 취향 루프 — 보조 역할.
- **D. 양식 지속 학습·확장 파이프라인 (채택)**.

## Recommended Approach: D
- **딥리서치(축1·검증됨)** = 차별 코어. 근거·수치 corpus 대조·출처.
- **양식 지속 학습·확장**: envato 자동 수집(`_queue`·이미 시작)·후추님 스타일 덱·새 소스 → 양식 라이브러리가 계속 성장. **gbrain(양식 brain·dream cycle enrichment)이 이 "계속 커지는" 엔진 후보**.
- 양식 컴포넌트(SVG·11유형 구현됨) = 라이브러리의 현재 스냅샷·계속 추가.
- 매칭(큐레이션) = 딥리서치 결과 → 많고 다양한 양식 중 선택 (보조·핵심 아님).

## Open Questions
- 양식 학습 = 자동 스타일 추출 어디까지? 후추님 수동 큐레이션 어디까지 개입?
- gbrain을 양식 라이브러리로 쓸지(capture envato·후추님 스타일·dream cycle 확장) — 후추님 검토.
- "양식 충분히 많다"의 기준? (몇 개부터 매번 다른 덱이 보장되나)

## Success Criteria
- **같은 주제 2번 돌리면 다른 양식 덱** 나옴(양식 다양성 = 1급 지표).
- 양식 라이브러리가 시간 따라 계속 커짐(1회성 X·지속 확장).
- 딥리서치 = 근거·출처 명시(진실주의)·텍스트 fallback 금지.

## Distribution / 사용
- 후추님 customer zero·본인 계속 활용. 외부 배포는 나중(무기 디깅 트랙).

## Next Steps
1. 양식 컴포넌트 11유형 검수·확정 (codex 4중 검수 대기 중).
2. 양식 수집 자동화 확장(envato `_queue` 계속)·라이브러리 구조 결정(gbrain 후보).
3. 딥리서치(축1) → 양식 매칭 → 시각 덱.
4. 같은 주제 2회 = 다른 덱 검증(양식 다양성 지표).

## What I noticed about how you think
- "양식이 적으면 할 때마다 동일해 보일 수밖에 없어" — A/B/C가 다 수렴한다는 걸 즉시 봤다. 양식을 "한 번 만들고 끝"으로 본 본부 PRD_v3를 정확히 교정.
- "엔바토 베끼면서 빈 양식 채운 것 뿐" — 양식의 진짜 가치는 후추님 스타일·지속 학습이지 envato 베끼기가 아니라는 통찰.
- 큐레이션을 심장으로 본 PRD_v3를 "딥리서치 + 양식 다양성"으로 바로잡음.

## ⚠️ 2026-06-19 교정 — 발표 작가 단계(②③) 신설 (아래 6/18 아키텍처를 대체)

실제로 돌려본 덱이 컨설팅 급에 한참 못 미쳤다. 근본 원인 = **6/18 흐름에 "발표 작가" 단계가 통째로 빠짐.** 흐름이 `리서치 → 매칭(양식선택) → 렌더`라, 보고서 마크다운을 기계적으로 잘라 슬라이드에 채우는 슬라이서만 있고 **틀+스토리·페이지 구성(작가)이 없다.** "같은 주제 2번=다른 덱(양식 다양성)"을 1급 지표로 본 것도 오판 — 1급은 **발표로서의 완성도**다.

정본 흐름(교정): **① 딥리서치 → ② 틀+스토리(LLM 작가) → ③ 페이지 구성(LLM 작가) → ④ 디자인 바인더(파이썬) → 렌더.**
- ②③ = 똑똑한 중국모델이 *작가* 노릇(지배 메시지·스토리 아크·재분류 섹션·한 장 한 메시지·BLUF·content_kind 라우팅). sinya 격리 안에서 돈다.

- 성공 기준(교정): 지배 메시지가 표지·결론에 반복 · 목차는 테마만 · 페이지마다 결론 먼저 · 원본 표 보존+하단 출처 · 꾸며내기 0(payload는 report에서만).
