# 덱 제작 플레이북 — 후추님 방식 (2026-06-27 정립)

> "2026 마케팅 트렌드 B(효율의 함정)" 빌드로 정립한 **반복 가능한 인간식 제작 플로우.** DECK_PIPELINE_SYSTEM의 운영 디테일판. 새 덱 만들 때 이 순서대로.

## 철칙 (어기면 사고)
1. **내용 먼저 — 틀에 우겨넣지 않는다.** 디자인부터 잡고 내용 끼워넣기 금지. **자료 → 내용 → 디자인** 순서 엄수. (후추님 반복 강조)
2. **색은 awwwards 수상작 / 펜톤 톤다운에서 뽑는다 — 클차장 임의 선택 금지.** (반복 위반 — 매 덱 점검. §9 프리셋 사용)
3. **발행 전 전 페이지 픽셀 검증.** 리뷰어(Gemini 등)의 "치명적 렌더 버그" 주장은 픽셀로 교차검증 — **자주 환각**(세로깨짐·%줄바꿈·표정렬 3건 다 헛다리였음). 진짜 값어치는 한국어·내용·여백 지적에.
4. **외부 레퍼런스(awwwards·경쟁 덱 등)는 학습 → 우리 것으로 흡수 → 소스는 잊는다.** 흡수 끝나면 계속 비교·참조하지 않는다. 우리 시스템(§9 프리셋·본 플레이북)만 SoT. (후추님 "흡수하고 잊어")

## 플로우 (7단계)
1. **자료 최대 수집** — findings 디제스트(`review/intake/content_*.md`) 전부 읽기. raw corpus는 노이즈라 X.
2. **여러 구조 방향(2~4안)** — 같은 자료에서 서로 다른 narrative spine 도출. **디자인 0·텍스트만.** 후추님이 흐름/전달로 택1. (예: A 인간역설 / B 효율의함정 / C 세 청중 / D 성숙도격차)
3. **내용 최대 채움** — 택한 구조에 들어갈 후보를 *다* 담음(들어갈 양보다 많이) → `authored/{deck}_content_maximal.md`(내용 SoT).
4. **키스톤 슬라이드 양식 2~3안** — 가장 중요한 1장으로 디자인 언어 결정. ⓐ흐름에 맞나 ⓑ내용 전달 잘 되나로 택1.
5. **전 슬라이드에 언어 적용 + 쳐내기** — 키스톤 언어로 나머지 빌드. 슬라이드당 핵심 1~3개만 살리고 나머지 부록/주석. *진짜 애매한 장만* 다시 2~3안.
6. **꽉 채움 + 대담함(awwwards)** — 빈 공간 = 큰 포컬·대형 볼드 타이포로 채움(작게 흩지 X). 다크↔라이트 리듬. grayout(승=강조색·패=회색). 카드 내부 여백 = 근거 띠로.
7. **검증·리뷰** — 헤드리스 `--print-to-pdf`(슬라이드당 1p) → 전 페이지 Read 검증 → codex/gemini/destroyer 리뷰 → 픽셀로 triage(진짜/과장/환각) → 진짜만 수정.

## 디자인 규약
- **폰트 = Pretendard 단일**(PDF·PPTX 일관 치환). 세리프 예쁨은 PDF 커버 악센트만.
- **팔레트 = 토큰 4개(`--g` 바탕·`--d` 딥/블록·`--ac` 강조·`--gray` 차트)만 교체** → 주제 적응. 프리셋 = `DECK_STRUCTURE_LIBRARY.md §9`(awwwards 6종: 모노·세이지·플럼·와인·잉크스틸블루·오커).
- 액션 타이틀(서술형) · 개조식(~함/~임) · 실명 2026 출처 엔드노트.
- 차트 = 그레이아웃 · 직접 라벨 · Y축 0.
- ⚠️ **클래스 이름 충돌 주의** — 슬라이드 `.s`와 자식 `.s`(부제)가 겹쳐 레이아웃 폭발 전례. 자식 클래스는 고유명으로.
